# 새 PC 에서 쓰기 (2026-10-15)

기업추적(뷰어 · 수집)과 Tech(차트 발굴)를 다른 PC 에서 돌리는 순서. 점검 · 설치 · 예약 작업 등록은 `새PC_설치.ps1` 한 개가 한다.

## 무엇이 어디로 오나

| 것 | git | 구글 드라이브 | 직접 옮김 |
|---|---|---|---|
| 코드 (기업추적 · Tech) | ✓ | ✓ | |
| 수집 원문 `기업추적_수집/` (수십 GB) · 캐시 `.cache/` | — | ✓ | |
| `.env` · `경로설정.txt` · `종목.txt` · `개인/`(매매 일지) | — | ✓ | |
| KIS 키 `%USERPROFILE%\KIS\config\kis_devlp.yaml` | — | — | **USB 등으로 직접** |
| 텔레그램 로그인 `%LOCALAPPDATA%\기업추적\telegram.session` | — | — | 새로 로그인 |
| 파이썬 · Tech 가상환경 · 예약 작업 | — | — | 스크립트가 만든다 |
| Claude 메모리 `%USERPROFILE%\.claude\projects\G---------Claude---\memory\` | — | — | 폴더째 복사하면 이어서 기억 |

**같은 구글 계정의 드라이브로 쓰는 것을 권한다.** GitHub 에서 받으면 코드만 오고 수집 원문 · 캐시가 없어 처음부터 며칠 수집해야 한다.

## 순서

1. **구글 드라이브 데스크톱** 설치 · 로그인 → `G:\내 드라이브\Claude` 가 보이는지. 드라이브 문자가 G: 가 아니면 `기업추적\경로설정.txt` 의 `DART_ENV_PATH` · `UNIVERSE_XLSX` 를 이 PC 경로로 고친다.
   - `Claude` 폴더를 오른쪽 클릭 → **오프라인으로 사용 가능** 으로. 스트리밍 상태면 파일 수만 개를 열 때마다 내려받아 매우 느리다.
2. **파이썬** — python.org 에서 Python 3.13 (64비트, 설치 때 'py launcher' · 'Add to PATH' 체크). 기업추적은 3.11 이상이면 32 · 64비트 모두 되고, Tech 는 64비트가 필요하다. 하나(3.13 64비트)로 둘 다 된다.
3. **KIS 키** — 옛 PC 의 `C:\Users\<이름>\KIS\config\kis_devlp.yaml` 을 USB 로 새 PC 의 같은 자리에 복사(드라이브 · git · 메신저 금지). 없으면 차트 발굴이 네이버 시세만으로 돈다.
4. **점검 → 설치** — PowerShell 에서:
   ```
   cd "G:\내 드라이브\Claude\주식\기업추적"
   powershell -ExecutionPolicy Bypass -File .\새PC_설치.ps1 -CheckOnly
   powershell -ExecutionPolicy Bypass -File .\새PC_설치.ps1
   ```
   '할 일' 줄이 남으면 그것부터 처리하고 다시 `-CheckOnly`.
5. **자동 작업** — 이 PC 에서 뷰어 · 밤 수집을 매일 돌릴 거면:
   ```
   powershell -ExecutionPolicy Bypass -File .\새PC_설치.ps1 -Schedule
   ```
   예약 작업 셋을 만든다 — 뷰어(매일 00:05 + 로그인 1분 뒤), 수집(매일 00:10), 점검(손으로). 뷰어가 저평가(06:30) · 차트 발굴 스캔(평일 20:15) · 수출 추적 갱신을 알아서 띄운다. 브라우저로 `http://127.0.0.1:8765`.
6. **텔레그램**(리포트 탭, 필요할 때만) — 터미널에서 `python 도구\텔레그램_로그인.py`, 전화번호 · 코드는 직접 넣는다.

## 두 PC 를 같이 쓸 때 — 지킬 것

- **자동 작업(-Schedule)은 한 PC 에서만.** 두 PC 가 같은 드라이브 폴더에 캐시를 동시에 쓰면 서로 덮고(드라이브가 `파일 (1).json` 같은 충돌 사본을 만든다) DART 하루 한도(약 2만 건)를 둘이 나눠 쓴다.
  - 옮겨 가는 거라면 옛 PC 에서: `Disable-ScheduledTask GiupChujeok_Viewer; Disable-ScheduledTask GiupChujeok_Collect`
- **뷰어도 한 번에 한 PC.** 다른 PC 에서 볼 때는 `기업추적_조회.bat`(조회 전용 — 아래 「보기만 할 때」)으로 연다. 그 PC 에서 `기업추적_뷰어.bat`(메인 뷰어)을 띄우면 캐시를 같이 쓰게 된다.
- **git 커밋 · 푸시도 한 PC 에서.** `.git` 폴더도 드라이브로 동기화되는데, 두 PC 가 동시에 건드리면 저장소가 깨질 수 있다. 다른 PC 에서 고쳤으면 동기화가 끝난 뒤(드라이브 아이콘 확인) 다른 PC 에서 이어 작업한다.
- 시험 서버는 `python -X utf8 서버.py --port 8766 --no-auto` (자동 작업 없이).

## 보기만 할 때 — `기업추적_조회.bat` (조회 전용, 2026-10-15)

메인 PC 만 자동 작업 · 계산 · 수집 · git 을 하고, 다른 PC 는 같은 드라이브로 받은 화면을 **보기만** 한다. 이때는 위 「순서」의 설치 스크립트 · KIS 키 · 예약 작업 · 텔레그램이 필요 없다.

1. **구글 드라이브 데스크톱** — 위 「순서」 1번과 같다(오프라인으로 사용 가능 권장).
2. **`G:\내 드라이브\Claude\주식\기업추적\기업추적_조회.bat` 더블클릭.**
   - 파이썬(3.9+)을 `where python` → `py -3` → `%LOCALAPPDATA%\Programs\Python\Python3*\` 순으로 찾는다. 없으면 영어 안내와 함께 python.org 를 연다 — 설치 첫 화면에서 'Add python.exe to PATH' 를 체크하고, 끝나면 다시 더블클릭.
   - 이 PC 에서 메인 뷰어(포트 8765)가 이미 떠 있으면 그 화면만 열고 끝, 조회 전용 서버(8770)가 이미 떠 있으면 그 화면만 열고 끝.
   - 처음 한 번: requests 가 없으면 `pip install --user requests openpyxl`, 바탕화면에 이 bat 을 여는 바로가기가 없으면 만든다(OneDrive 로 옮긴 바탕화면도). 이름은 '기업추적' — 같은 이름의 바로가기가 이미 다른 것(예전 메인 PC 의 메인 뷰어 바로가기가 따라온 것 등)을 열면 그건 그대로 두고 '기업추적 조회' 로 만든다(이름이 아니라 가리키는 대상으로 가린다). 그다음부터는 그 바로가기로 연다.
   - 조회 전용 서버를 `pythonw`(검은 창 없음)로 띄우고, 포트가 열리면(최대 90초) 브라우저로 `http://127.0.0.1:8770` 을 연다. 색인은 메인 PC 가 만든 `.cache/색인.json` 을 그대로 읽어 몇 초면 열린다. 서버가 곧바로 꺼지면(`pythonw.exe` 가 하나도 안 남으면) 90초를 다 기다리지 않고 로그 위치를 알려 준다. 90초가 지나도 안 열리면 — 드라이브에서 처음 읽느라 느린 것일 수 있다 — 1~2분 뒤 다시 더블클릭하면 열려 있는 8770 을 바로 연다.
3. 화면 맨 위의 띠 — "조회 전용 — 이 PC 는 보기만 합니다. … (색인 YYYY-MM-DD HH:MM)". 시각은 메인 PC 가 색인을 마지막으로 쓴 때(드라이브가 그 파일을 받아 온 판)다.

이 PC 에서 일어나는 일 — `viewer_readonly.py` 가 서버 코드를 읽기 **전에** `조회전용.py` 를 켜고 `서버.py --readonly --no-auto --port 8770` 을 부른다.

- **드라이브 파일을 하나도 바꾸지 않는다.** 서버가 기업추적 폴더 아래에 쓰려는 것(캐시 · 로그)은 `%LOCALAPPDATA%\기업추적\조회전용\shadow` 의 같은 자리로 가고, 다시 읽을 때는 거기 것을 먼저 본다. shadow 는 띄울 때마다 비운다 — 지난번 것이 드라이브가 새로 받아 온 메인 PC 캐시를 가리지 않게. `__pycache__` 도 만들지 않는다.
- **바깥을 부르지 않는다**(DART · 네이버 · KIS · 관세청 · 텔레그램 — 127.0.0.1 밖 연결 · UDP · DNS 이름 묻기까지 막힘), **다른 프로그램을 띄우지 않는다.** 재무 · 공시 목록(호재 · 수주 공시) · 낙폭 공시 · 컨센서스 · 보컬 목록/재무 요약 캐시는 만기가 지나도 있는 그대로 쓰고, 캐시가 없으면 묻지 않고 빈 칸으로 둔다. 저평가 · 산업 성장률 · 억울한 낙폭 · 기록 채점 · 보컬 · 업종 분류 · 내러티브 시장 중앙은 저장된 결과가 묵었어도 다시 계산하지 않는다(다시 받으려다 막혀 빈 값이 되거나, 낡은 재료에 '방금 계산' 시각만 붙지 않게). 가속도 '지금 PER' 다시 쌓기 · 내러티브 뉴스 받기도 하지 않는다(내러티브는 받아 둔 제목으로 — "조회 전용 — 뉴스는 메인 PC 가 받는다").
- 쓰기 돌리기를 거치지 않는 길(`io.FileIO` · `os.link` · sqlite · 3.12+ `shutil.copy2` · junction/subst 로 가리키는 경로 · C 수준 socket)은 파이썬 감사 훅이 마지막으로 막는다(PermissionError · 연결 거절).
- **자동 갱신 루프(저평가 06:30 · 밸류체인 · 리포트 · 산업 · 차트 발굴 · 가속도 · 미리 계산 · 수출)를 켜지 않고, 색인을 다시 만들지 않는다.**
- **일을 시키는 요청은 거절한다** — '다시 계산'(force=1) · 차트 발굴 실행(run=1) · 새로 고침(refresh=1) · 전 종목 미리 계산 · 색인 갱신 · 리포트 '지금 받기' · 수출 자동 받기 켜기/끄기 · 매매 일지 쓰기(POST) 는 403 "조회 전용 — 계산 · 수집 · 쓰기는 메인 PC 에서". '전 종목 미리 계산' · '색인 갱신' 단추는 숨는다.
- 보기만 하는 요청은 그대로 — 캐시에 있으면 바로, 메인 PC 가 아직 안 만든 판(처음 여는 회사의 풍경 등)과 메모리에만 있는 표(시너지 발굴 · 수주잔고 — 처음 열면 1분 안팎)는 이 PC 가 캐시만으로 **한 번** 계산해 보여 주고 결과는 shadow 에만 남는다(바깥을 못 부르니 메인 PC 판보다 빈 칸이 있을 수 있다). 그 뒤로는 시간이 지나도 다시 계산하지 않는다 — 새 판은 뷰어를 다시 띄우면 드라이브에서 읽는다. 시너지 '다시 계산' · 리포트 '지금 받기' · 내러티브 '뉴스 새로 받기' 단추는 숨는다.
- 로그: `%LOCALAPPDATA%\기업추적\조회전용\viewer_ro.log`. **Microsoft Store 파이썬**이면 Windows 가 이 자리를 `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation.Python.3.xx_<게시자>\LocalCache\Local\기업추적\조회전용\` 로 옮긴다(shadow 도 같이) — `python viewer_readonly.py --where-log` 가 실제 위치를 찍고, bat 도 실패 안내에 그 위치를 보인다. 끄기: 작업 관리자 → 세부 정보 → `pythonw.exe`(명령줄에 `viewer_readonly.py`) 끝내기, 또는 PC 를 끄면 된다.
- 메인 PC 에서 확인할 때(바탕화면 바로가기를 만들지 않고): `python -X utf8 viewer_readonly.py --no-shortcut --port 8770`. bat 의 판단만 보려면 `set GIUP_RO_DRYRUN=1` 뒤 bat 실행 — 브라우저 · pip · 바로가기 · 서버 띄우기를 하지 않고 할 일을 찍는다.
