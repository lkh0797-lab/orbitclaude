# 탑픽 — 실적은 좋아졌거나 사상 최대인데 시가총액은 아직 (2026-10-20)

## 사용자 요청(그대로)

분기보고서로 "실적이 개선됐거나 사상 최대를 경신했는데, 시가총액은 아직 그만큼 오르지 않은 종목"을 찾는다. 백테스트로 이 전략이 단순 저PER 전략보다 나은지 검증하고, 최신 공시 기준 후보 리스트를 만든다.

절대 규칙
1. 시점 기준은 분기말이 아니라 보고서 접수일. 어떤 날의 신호든 전일까지 접수된 보고서와 전일 종가 시총만 쓴다.
2. 임계값은 고정. 성과를 좋게 만들려고 바꾸지 않는다. 대신 임계값별 ±50% 민감도 표만 만든다.

신호(초안): A 영업이익 YoY ≥ +20% 그리고 매출 YoY ≥ +5% 또는 적자→흑자(YoY 상한 +200%) · B TTM 영업이익 사상 최대(12분기↑) · C1 TTM 영업이익 증가율 − 시총 증가율 ≥ +30%p ·
C2 POR 자기 20분기 분포 하위 30%(TTM ≤ 0 제외) · 20일 평균 거래대금 ≥ 10억. 후보 = (A 또는 B) ∧ C1 ∧ C2 ∧ 유동성. 순위 = 세 값의 후보 안 백분위 평균.
"이렇게 초안을 잡았다. 더 좋은 대안이 있다면 그렇게 진행하도록."

## 설계 검토(에이전트 셋 + 반박 검증) 뒤 결정 — 문턱은 그대로, 정의 · 적격 · 비교 방법만 보강

| 검토가 찾은 것 | 결정 |
|---|---|
| 시점: TTM 창 안 정정 분기 · 늦은 정정 접수일이 미래 값을 새어 들인다 | '알게 된 날' = 원본 정기보고서 접수일(색인 filed_meta). 값은 마지막 원장(정정값일 수 있음)으로 두고 flag `late_amend`(기준일 − 원본 > 45일) · `q_amended`, 민감도에 '정정 분기 제외' 줄 |
| 기저 0 근처 YoY 가 A 를 통과하고 순위를 채운다 | 저장소 규칙 재사용: 전년 영업이익 < 매출 1% 이면 A1 안 봄(`tiny_base`), 흑자 전환인데 이익 < 매출 1% 는 A2 아님(`thin_profit`). 순위 성분에서도 뺀다 |
| 금융(매출 없음 · IFRS17 단절) · 순수 지주(지분법) | 적격 밖 — 최신 후보에 '참고' 묶음으로만. KSIC 64~66 또는 basis=영업이익 · 최근 4분기에 영업이익 > 매출 |
| 기준선이 탑픽보다 어리고 거친 집합에서 나온다 | 적격 집합 U(s) 하나(온전한 신호 분기 · 150일 안 보고서 · 비금융 · 비지주 · 지금/1년 전 시총 · 이력 12분기↑ · 거래 자료) 안에서 모든 묶음 |
| 저PER 비교는 같은 날 · 같은 철로 — 회사 단위 구간만으론 좁다 | 주 지표 사전 등록: 사건 패널 · 12개월 · 같은 철(같은 분기 보고서) 저PER 하위 30% 와의 철별 중앙 차이 · 철 단위 부트스트랩 90% 구간. 회사 단위 구간도 함께, 넓은 쪽을 본다 |
| 잠정실적 · 손익구조변동 공시가 2~7주 먼저 알린다 | 신호엔 안 쓴다(규칙 1). '먼저 알려진 날'과 그 뒤 주가 변화를 표에, 있음/없음 나눠 보기 |
| 신호일 종가가 공시 반응 전 가격일 수 있다 | 기본은 사용자 규칙(접수일 종가 · 다음 거래일 진입 = 화면 사용과 같다). 민감도에 '사건 신호일 하루 뒤' 줄 |
| 거래량은 원주 수 · 분할 배수를 분기째 쓰면 분기 안 분할이 틀린다 · 정지 종목이 통과 | 분할 날짜 = 공시목록의 분할 · 무상증자 · 병합 · 감자 결정 공시 뒤 거래량이 뛴 날(`split_days`, 공시 없는 배수 변화는 잡음). 시장 달력 20거래일, 봉 없는 날 0 |
| 역산 주식수 잡음 · 증자 희석 | 믿을 만한 자기 분기(순이익 ≥ 매출 0.5% · 제외 아님 · unit/cut 없음) 가까운 4개 중앙값. flag `sh_wobble` · `sh_up` |
| 경기 고점에서 B 와 C2 가 같이 켜진다(가치 함정) | flag `opm_peak`(4분기 합 영업이익률 자기 상위 10% · 매출보다 마진이 끌어올림) — 빼지 않고 표시 · 나눠 보기 |
| 월말 패널은 같은 공시를 석 달 되풀이 센다 | 월말은 보조. 행마다 kind(new · held · price) |
| 칸이 70개 넘으면 다중검정 | 결론은 주 지표로만, 나머지 표는 '보조' 표시, 민감도는 부호 뒤집힌 칸 수 한 줄 |
| ±30% 하루 움직임 재보정(시너지._adjusted) | 쓰지 않는다 — .cache/price 그대로 |
| 관리종목 · 실질심사 | 최신 후보에 공시목록 위험 분류(공시위험.json) 꼬리표 |

반박 검증에서 버린 것: 순위 백분위가 극단값에 끌린다(순위 변환이라 아님) · 분기 단위 분할 배수(날짜로 바꿔 해결) · 분기별 표(설명용으로만 넣음) · 재보정 금지(이미 안 씀).
