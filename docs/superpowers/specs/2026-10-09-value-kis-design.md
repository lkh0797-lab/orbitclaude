사용자 요청: '차트 발굴 안에 저평가V2 형식을 옮겨라 · 저평가V2 는 탭에서 없애라 · 저평가 종목이라는 이름으로 보컬 칩 옆에 · 증권사 API 로 개선할 수 있는 것은 전반적으로.'

## 구조 — Tech 가 KIS 창구, 기업추적은 결과 파일을 읽는다
기업추적 뷰어는 32비트 파이썬이라 Tech(64비트 venv)가 KIS 를 부르고 토큰도 하나만 쓴다.

```
06:30 기업추적 저평가 계산 ──▶ .cache/value/tech_export.json ─┐ (CHART_SCREENER_VALUE_JSON)
                                                              ▼
16:00 차트 발굴 스캔(Tech): KIS 상태 · 실거래대금 · 수급 · 의견 · 실적 → 패턴 → 리포트(후보 · 300억 레이더 · 업종 · 저평가 종목 탭)
                                                              │
                                     Tech/cache/kis/snapshot.json ──▶ 기업추적 _val_apply_risk(관리 · 정지 · 정리매매 · 투자위험 → 관찰)
```

## 기업추적(이 저장소)
- 저평가V2 탭 · 서버 계산 · 라우트 · 06:30 V2 단계 제거(엔진 · 검증 도구 · 옛 결과는 남김). 차트 발굴 붙인 뒤 생긴 `TECH` 이름 충돌 버그가 함께 없어진다.
- `_val_export_tech` — 저평가 · 관찰 행(공시 위험 · KIS 상태 반영 뒤)을 v1 스키마로.
- `_kis_snapshot` · `_kis_tags` — 스냅샷(5일 안)으로 등급 내리기 · 태그.
- `tech_run(auto)` — 값 파일 경로를 넘기고, 자동 실행이면 `--skip-holiday`(Tech 가 아는 경우만).

## Tech(chart_screener)
- `data/kis_market.py` — 공유 클라이언트 1개 · 스레드 · 날짜별 캐시: 상태(전 종목) · 실거래대금(전 종목, 최근 100일, 매일 이어 붙여 이력이 길어짐) ·
  수급 · 의견 · 실적(후보 + 저평가 종목) · 휴장일 · 스냅샷.
- 스캔 연결 — `scan --kis {auto,on,off}`(auto = 되면 KIS, 아니면 네이버 + 이유), `--skip-holiday`;
  거래정지 · 정리매매 · 관리종목 · 투자위험은 후보에서 빼서 '탈락'에 사유, 경고 · 단기과열 · 증거금 100%는 이름 옆 표시;
  패턴 · 시장 폭 · 업종 · 레이더 · 보컬 전에 추정 거래대금을 실거래대금으로; CAN SLIM I · 20일 수급은 KIS(네이버는 대체);
  후보 표에 목표가 괴리(↑ 상향 건수) · EPS(E) 성장 열; 리포트 머리에 증권사 자료 한 줄.
- 관찰용 패턴 둘을 기업추적에서 옮김 — `absorb` 바닥 투매 흡수 · `stage2` 바닥 탈출(와인스타인 1→2단계). 후보를 스스로 만들지 않는다.
- `undervalued` '저평가 종목' — 칩(보컬 다음, 후보 가운데 저평가만) + 탭(저평가 전부: 범위 토글 · 셋업 카드 · 표 · 미니차트, 저평가 등급 비후보는 짧은 일봉을 넣어 큰 차트도).
- 점수 · 매수 계획 · 실시간 감시에는 보컬 · 저평가 · 바닥형 모두 넣지 않는다(관찰용).

## 호출량 · 실패
하루 ≈ 상태 2,450 + 거래대금 2,450 + (수급 · 의견 · 실적) × 후보 · 저평가 ~500 ≈ 6,000회, 초당 15회 ≈ 7분. KIS 가 안 되면 네이버로 지금처럼 돌고 리포트에 이유.
