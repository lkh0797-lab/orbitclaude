# 기업추적 (orbitclaude)

DART 전자공시에서 종목별 **정기보고서(사업·반기·분기)** 원문을 받아
섹션 단위 텍스트로 쪼개 쌓고, **직전 보고서 대비 무엇이 달라졌는지**를
브라우저에서 시계열로 읽는 도구.

기업의 성장 궤도를 추적하는 것이 목적이다. 15년치를 처음부터 읽는 대신,
**회사가 문장을 다시 쓴 해**만 찾아 그 변화만 읽는다.

- `기업추적_실행.bat` — 수집기. 원문을 받아 쌓는다.
- `기업추적_뷰어.bat` — 뷰어. `http://127.0.0.1:8765` 로 열린다.

## 설치

필요한 것: **Python 3.9+**, **DART OpenAPI 키**(무료,
[opendart.fss.or.kr](https://opendart.fss.or.kr) 에서 발급).

```bash
git clone https://github.com/lkh0797-lab/orbitclaude.git
cd orbitclaude
pip install requests openpyxl
```

**1. API 키.** 폴더에 `.env` 파일을 만들고 한 줄:

```
DART_API_KEY=발급받은키
```

환경변수 `DART_API_KEY` 로 줘도 되고, 다른 프로젝트의 `.env` 를 재사용하려면
`경로설정.txt` 에 `DART_ENV_PATH=경로` 를 적으면 된다.

**2. 대상 종목.** `종목.예시.txt` 를 `종목.txt` 로 복사하고 원하는 종목코드를 적는다.

**3. 수집.** `기업추적_실행.bat` 더블클릭 (또는 `python 기업추적_수집기.py --years 15`).

**4. 열기.** `기업추적_뷰어.bat` 더블클릭.

> 수집한 공시 원문은 저장소에 없다. DART 자료라 재배포하지 않고, 15년 × 500종목이면
> 수십 GB다. 각자 수집기를 돌려 채우는 구조다.

# 뷰어

`기업추적_뷰어.bat` 더블클릭 → 브라우저가 열린다. 검색창에 기업명을 넣으면
그 회사의 전 기간 보고서가 한 화면에 들어온다.

| 탭 | 하는 일 |
|---|---|
| **궤도** | 보고서마다 직전 대비 **변화점수** 막대. 높은 분기 = 무슨 일이 있었던 분기 |
| **변화 브리핑** | 그 보고서의 **재무지표 15종**(변화량·변화율 포함)과 **무엇이 달라졌는지** 중요도 순 자동 정리 |
| **연혁** | 연도별 보고서 타임라인. 카드를 누르면 본문 |
| **본문** | 섹션 읽기. 보고서·섹션을 드롭다운으로 갈아끼움 |
| **섹션 궤적** | 같은 섹션을 연도별로 비교한 **유사도 막대**. 짧은 막대 = 말이 크게 바뀐 해 |
| **변경점 비교** | 두 시점 문단 단위 diff. 초록=추가, 빨강=삭제 |
| **전문검색** | 회사 전 보고서 전문 검색. **최초 등장 시점**을 짚어준다 |
| **키워드 추이** | 용어별 등장 횟수 시계열 그래프 |
| **분석 레시피** | 아래 워크플로우를 버튼 하나로 |

수집을 더 돌린 뒤에는 헤더의 **색인 갱신**을 누르면 새 자료가 붙는다.

## 재무지표 (변화 브리핑 상단)

보고서마다 15개 지표를 **직전 같은 종류 보고서 대비 변화량·변화율**과 함께 세운다.

```
PER 28.45배  +17.62배 +162.7%      자산 567조   +52.4조 +10.2%
PBR  2.51배   +1.72배 +217.0%      자본 436조   +34.1조  +8.5%
ROE 10.36%    +1.80%p  +21.0%      부채 131조   +18.3조 +16.3%
EPS 6,605원   +1,655원  +33.4%      유보금 407조 +31.6조  +8.4%
BPS 74,869원  +7,161원  +10.6%      유보율 45,296.2%     +8.4%
                                    부채비율 29.9% +2.0%p +7.2%
```

출처와 계산:

| 지표 | 산출 |
|---|---|
| 자산·부채·자본·자본금·이익잉여금 | DART `fnlttSinglAcntAll` 원장 |
| EPS | DART `기본주당이익` (보고서에 적힌 값 그대로) |
| BPS | 자본총계 ÷ (발행주식총수 − 자기주식), 주식총수는 DART `stockTotqySttus` |
| 부채비율 | 부채총계 ÷ 자본총계 × 100 |
| 유보금 | 자본잉여금 + 이익잉여금 (자본잉여금 없으면 주식발행초과금으로 대체) |
| 유보율 | 유보금 ÷ 자본금 × 100 |
| ROE | 당기순이익 ÷ 자본총계 × 100 (기말 자본 기준) |
| 영업이익률 | 영업이익 ÷ 매출액 × 100 |
| **PER · PBR** | 주가 ÷ EPS, 주가 ÷ BPS. **주가는 네이버 일별 시세**, 그 보고서 **접수일 종가** |

주의:

- **PER 은 사업보고서에서만 낸다.** 분기·반기 EPS 는 누적치라 그대로 나누면 과대평가된다.
  PBR 은 시점 잔액이라 전 기간 산출한다.
- ROE 도 분기·반기는 누적 순이익 기준이라 연율이 아니다.
- 계정을 잡을 때 IFRS 표준태그(`ifrs-full_Assets` 등)를 먼저 보고 없으면 계정명으로 찾는다.
  자본변동표(SCE)는 '자본총계'가 여러 줄 나와 값이 섞이므로 재무상태표·손익계산서만 읽는다.
- 재무 데이터는 `.cache/fin/`, 주가는 `.cache/price/` 에 저장된다. 주가는 하루 단위 갱신.

## 왜 이렇게 만들었나 — 읽는 순서

15년치를 1번 보고서부터 읽는 사람은 없다. 순서는 이렇다.

1. **섹션 궤적**에서 「사업의 내용」 유사도를 본다. 사업보고서끼리 연 단위로.
2. 막대가 짧은 해(= 회사가 문장을 다시 쓴 해)만 3~4개 고른다.
3. 그 구간만 **변경점 비교**로 연다. 초록 문단이 그 해에 새로 생긴 사실이다.
4. 새로 나온 단어를 **키워드 추이**에 넣어 언제부터 몇 번 쓰였는지 본다.
5. **전문검색**으로 그 말의 최초 등장 보고서를 찾아 원문 맥락을 읽는다.

삼성전자 실측: 「사업의 내용」 연 단위 유사도가 2020→2021 구간에 **21.4%**
(63,675자 → 39,793자)로 떨어진다. 15년 중 가장 크게 다시 쓴 해다.
HBM은 2015년 사업보고서에 **1회** 처음 나와 2023년 **31회**까지 늘었다.

## 실행

가장 쉬운 방법 — `기업추적_실행.bat` 더블클릭. `종목.txt` 에 적힌 종목을 최근 10년치 훑는다.
옵션은 bat 에 그대로 붙여도 먹는다: `기업추적_실행.bat --years 15`

```bash
python 기업추적_수집기.py                       # 종목.txt 전체, 최근 10년
python 기업추적_수집기.py 403870 005930         # 종목코드 직접 지정
python 기업추적_수집기.py 005930 --years 15     # 15년치
python 기업추적_수집기.py 005930 --all          # DART 개시(1999)부터 전부
python 기업추적_수집기.py 005930 --from 20100101
python 기업추적_수집기.py 005930 --skip-amended # [기재정정] 건 제외
python 기업추적_수집기.py 005930 --sleep 1.5    # 호출 간격 늘리기
```

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--years N` | 최근 N년 | 10 |
| `--all` | 1999년 DART 개시부터 전부 | — |
| `--from YYYYMMDD` | 시작일 직접 지정 | — |
| `--skip-amended` | `[기재정정]` 재공시 건 제외 | 포함 |
| `--sleep 초` | DART 호출 간격 | 0.8 |
| `--max-calls N` | 이번 실행에서 쓸 DART 호출 상한. `0`이면 무제한 | 18000 |
| `--limit N` | 종목.txt 위에서 N종목만 | 전체 |
| `--with-audit` | 감사보고서도 수집 (상장 전 이력 소급) | 안 함 |

## 상장 전 이력 — `--with-audit`

**정기보고서는 상장사 의무다.** 상장 전에는 아예 존재하지 않는다.
그래서 최근 상장 종목은 `--years 15` 를 줘도 상장 이후만 나온다.

HPSP(2022년 7월 코스닥 상장)가 그 예다. 정기보고서 최초가 2022-09 분기보고서고,
1999년부터 뒤져도 그 앞은 없다.

메우는 길은 **감사보고서**다. 외부감사 대상이면 비상장이어도 매년 제출하고,
재무제표가 통째로 붙어 있다. `--with-audit` 을 주면 같이 받는다.

```
정기보고서 20건 + 감사보고서 4건   접수 20190403 ~ 20260814
   [  1/24] 2018-12 감사보고서   섹션 3개 / 20,771자
```

HPSP는 이걸로 2022 → **2018년**까지 소급됐다. 더는 못 간다 —
2018년 재무제표가 "제 2(당) 기", 즉 2017년 설립이라 회사 이력 자체의 시작점이다.

감사보고서는 섹션이 3개(감사의견 / 재무제표 / 감사 실시내용)뿐이라 정기보고서보다
훨씬 가볍다. 호출 수는 종목당 목록 1회 + 보고서당 1회가 더 든다.

## 일일 한도와 이어받기

**DART 일일 한도 20,000건. 이게 진짜 병목이다** (용량 아님).
보고서 1건당 호출 1회 + 종목당 목록 1회.

| 규모 | DART 호출 | 시간 | 용량 |
|---|---|---|---|
| 100종목 × 15년 | ~5,100 | ~1.7시간 | ~1.5GB |
| 300종목 × 15년 | ~15,300 | ~5.2시간 | ~4.4GB |
| 500종목 × 15년 | ~25,700 | ~8.7시간 | ~7.4GB |

500종목 15년치는 **하루에 안 끝난다.** `--max-calls` 에 걸리면 깔끔히 멈추고
어디까지 했는지 찍는다. 자정에 한도가 초기화되니 다음날 같은 명령을 다시 돌리면
받다 만 곳부터 정확히 이어받는다. 종료코드 3이 "한도 소진, 내일 계속" 이다.

## 종목 추가

`종목.txt` 에 6자리 종목코드를 한 줄에 하나씩. `#` 뒤는 메모.

## 출력 구조

```
기업추적_수집/
  삼성전자_005930/
    목록.csv                 <- 보고서 색인 (연월/종류/접수번호/섹션수/글자수)
    2011-06_반기보고서_20110829000254/
      01_【 대표이사 등의 확인 】.txt
      02_I. 회사의 개요.txt
      03_II. 사업의 내용.txt
      ...
      _완료.txt              <- 수집 완료 표시
```

각 `.txt` 첫 두 줄은 출처 헤더(기업명·보고서명·접수번호·섹션명), 그 아래가 본문.

## 이어받기

`_완료.txt` 가 있는 보고서는 건너뛴다. 창을 닫든 네트워크가 끊기든 다시 실행하면
받다 만 곳부터 이어진다. 특정 보고서를 다시 받으려면 그 폴더만 지우면 된다.

장시간 실행 대비:

- 통신 오류는 2·4·8초 backoff 로 3회 재시도
- DART 한도 초과(020)·점검(800) 같은 건 즉시 중단하고 사유를 찍는다. 받은 건은 남는다
- `Ctrl+C` 로 끊어도 안전

## 주의

- `.cache/CORPCODE.xml` 은 전체 상장사 고유번호 목록(약 29MB). 하루 지나면 자동 갱신.
  구글 드라이브 동기화가 부담되면 지워도 되고, 다음 실행 때 다시 받는다.
- DART 구버전 문서(대략 2022년 이전)는 줄바꿈을 `&cr;` 라는 자체 엔티티로 쓴다.
  표준 HTML 엔티티가 아니라 파이썬 `html.unescape` 가 모르고 그냥 흘려보낸다.
  `DART_ENTITIES` 에서 개행으로 바꿔준다. 새 엔티티가 나오면 여기 추가하면 된다.
  모르는 `&xxx;` 를 싸잡아 지우지는 않는다 — 본문의 `AT&T;` 같은 걸 다치게 하니까.
  점검: `grep -rhoE "&[a-zA-Z][a-zA-Z0-9]{1,10};" 기업추적_수집 | sort -u` 가 비어야 정상.
- `기업추적_실행.bat` 은 **의도적으로 ASCII만** 쓴다. cmd.exe 가 .bat 안의 한글을
  깨뜨려서 실행이 통째로 실패하기 때문. 한글 출력은 Python 쪽에서 나온다.
  같은 이유로 .bat 은 한글 이름 파이썬 파일을 직접 부르지 않고 `run.py` 를 거친다.
