# 기업추적 (orbitclaude)

DART 전자공시에서 종목별 **정기보고서(사업·반기·분기)** 원문을 받아
섹션 단위 텍스트로 쪼개 쌓고, **직전 보고서 대비 무엇이 달라졌는지**를
브라우저에서 시계열로 읽는 도구.

기업의 성장 궤도를 추적하는 것이 목적이다. 15년치를 처음부터 읽는 대신,
**회사가 문장을 다시 쓴 해**만 찾아 그 변화만 읽는다.

- `기업추적_실행.bat` — 수집기. 원문을 받아 쌓는다.
- `기업추적_뷰어.bat` — 뷰어. `http://127.0.0.1:8765` 로 열린다.

## 설치

필요한 것: **Python 3.9+**, **DART OpenAPI 키**(무료,
[opendart.fss.or.kr](https://opendart.fss.or.kr) 에서 발급).

```bash
git clone https://github.com/lkh0797-lab/orbitclaude.git
cd orbitclaude
pip install requests openpyxl
```

**1. API 키.** 폴더에 `.env` 파일을 만들고 한 줄:

```
DART_API_KEY=발급받은키
```

환경변수 `DART_API_KEY` 로 줘도 되고, 다른 프로젝트의 `.env` 를 재사용하려면
`경로설정.txt` 에 `DART_ENV_PATH=경로` 를 적으면 된다.

**2. 대상 종목.** `종목.예시.txt` 를 `종목.txt` 로 복사하고 원하는 종목코드를 적는다.

**3. 수집.** `기업추적_실행.bat` 더블클릭 (또는 `python 기업추적_수집기.py --years 15`).

**4. 열기.** `기업추적_뷰어.bat` 더블클릭.

> 수집한 공시 원문은 저장소에 없다. DART 자료라 재배포하지 않고, 15년 × 500종목이면
> 수십 GB다. 각자 수집기를 돌려 채우는 구조다.

## 변화 궤도 — 점수 읽는 법 (궤도 탭)

막대 높이는 **평소 대비 배수**다. 1× = 이 회사 **같은 종류 보고서**(사업·반기·분기 따로)가 보통 새로 쓰는 분량의 중앙값.
사업보고서는 원래 분기보다 길어서 원점수로 세우면 12월 막대가 늘 튀어 보인다 — 종류별로 나눠 맞춘다.

- **분량** = Σ 섹션 중요도 × (새로 쓴 글자 + 0.6 × 지운 글자). 중요도는 `서버.py` 의 `SECTION_WEIGHT`
  (사업의 내용 1.0 · 경영진단 0.95 · 투자자 보호 0.85 · 주주·재무 0.7 … 부속명세서 0.05). 숫자만 바뀐 표·문단은 세지 않는다.
- **등급** (`ORBIT_TIERS`) — 보고서 728건 분포로 경계를 잡았다.

  | 등급 | 배수 | 뜻 | 흔한 정도 |
  |---|---|---|---|
  | 격변 | 2× 이상 | 사업 설명이 통째로 바뀜. 반드시 읽을 것 | 25건 중 1건 |
  | 큼 | 1.5–2× | 한 섹션 이상이 새로 쓰임. 훑어볼 것 | 8건 중 1건 |
  | 평소 | 0.6–1.5× | 분기마다 있는 문구 손질 | 10건 중 7건 |
  | 조용 | 0.6× 미만 | 숫자·날짜만 갱신 | 8건 중 1건 |

- 예전 **변화점수**(섹션별 √분량 합)는 원장에 '원점수'로 작게 남겼다. 제곱근이라 1.4배만 돼도 상위 5%여서 감이 안 온다.
- **한 줄 요약** (`brief_gist`) — 점수가 큰 섹션(최대 3곳)마다 한 줄. 직전 보고서의 어떤 문단과 낱말이 절반 넘게 겹치면
  표현만 고친 것으로 보고 뺀다. 남은 새 문단에서 범주 낱말(수주·증설·M&A…)·새로 등장한 낱말·금액·날짜가 든 완결 문장을 골라
  '~함'체로 80자 안에 줄인다. 회계 상용구(기준서·공정가치·전환가격 조항 등)와 서식 안내는 거른다.
  새 사실이 안 잡히면 '문구·서식 손질 위주'로 적는다. 앞선 보고서에 이미 나온 문장은 원장에서 '이어짐'으로 흐리게.
- 요약은 브리핑 캐시(`.cache/brief/…json`)에 `gist`·`gist_v` 로 붙는다. 규칙을 바꾸면 `GIST_V` 를 올린다 —
  브리핑 전체를 다시 만들지 않고 요약만 뒤에서 다시 뽑는다(화면은 1초 안에 뜨고 요약이 채워져 간다).

## 변화 브리핑 — `/api/invest` (2026-10-01 개편)

**비교 대상 = 전년 동기**(2026-10-01, `baseline_yoy`): 분기보고서도 작년 같은 분기와 견준다(1Q↔작년 1Q, 3Q↔작년 3Q).
그 전에는 '같은 종류 직전'이라 1분기가 반년 전 3분기와 맞대졌다(셀트리온 26.1Q 매출 +11% → 전년 동기로 +36%).
사업·반기보고서는 원래 1년 전과 견줬다. 비교 짝은 `brief_pair`(캐시 `.cache/brief_pair/`), 재무는 `financials(c, rep, (base, kind))`.
궤도 · 평소 분량(×배) · 섹션 궤적은 그대로 '같은 종류 직전' 짝(`build_brief`)으로 잰다. 직전 3개월 비교는 아래 '분기 변화' 탭.

## 분기 변화 — `/api/quarter` (변화 브리핑 옆 탭, 2026-10-01)

보고서가 나올 때마다(3개월마다) **바로 앞 공시**와 맞대어 최근 8번을 이어 본다 — 변화 브리핑(전년 동기)과 짝.
- 사슬: 정정 빼고 분기·반기·사업보고서를 시점순으로(`_qtr_chain`, 최근 9건 → 8쌍).
- 숫자: 분기 단독 매출·영업이익·순이익(`matrix_cached` — 실적 탭과 같은 재무 매트릭스 캐시, 사업보고서 분기 = 연간 − 3분기 누적),
  직전 분기 대비 · 전년 동기 대비 · 이익률 변화. 표시: 흑자/적자 전환, 전년 동기 증가율 ±10%p 가속/둔화, 이익률 ±3%p.
- 새로 쓴 것 = 직전 공시에 없고 **지난 12개월 공시(작년 같은 분기 포함) 어디에도 없던 문장**(그 섹션 안에서) — 시장이 이미 읽은 말을 빼고.
- 빠진 것 = 직전 공시에 있고 이번엔 없으며 **같은 종류 직전 보고서에도 있던 문장**(그 종류에 늘 쓰던 말) — 사업보고서에만 있는 절이 '빠졌다'로 잡히지 않게.
- 신호 뽑기는 변화 브리핑과 같은 `_inv_collect`(known · regular 인자), 크기 · 같은 사건 묶기는 `_inv_refine`.
- 캐시 `.cache/quarter/<코드>/<접수번호>.json`(QTR_V). 처음 한 번은 8쌍을 맞대느라 1~2분 — 화면이 4초마다 다시 읽으며 최근 것부터 채운다.

**파이프라인 — 수주가 이익이 되기까지**(분기 변화 맨 위, `_qtr_pipe`). 주가는 결국 이익(EPS) 성장에 수렴하고, 수주가 납품돼 매출 · 이익으로 찍히기까지
물리적 시간이 걸린다. 그 사슬을 위(앞단)에서 아래(결과 · 가격)로 한 판에 놓는다 — 최근 12분기, 칸 = 전년 같은 분기 대비.
- 씨앗: 신사업 · R&D 새 문장 / 수주: 수주·계약 새 문장, 수주잔고(본문 `수주.py`, 잔고 ÷ 최근 4분기 매출 = 몇 년치), 선수금(계약부채 유동+비유동, 없으면 선수금)
- 생산: 재고자산 + 계약자산(미청구공사) / 설비: 증설 새 문장, 유형자산 취득(현금흐름표) 최근 4분기 합
- 결과: 매출 · 영업이익 · 지배주주 순이익(최근 4분기 합) / 가격: 분기 말 종가(분할 보정), PER(그날 실제 종가 ÷ 최근 4분기 EPS)
- 시차: 앞단의 전년 대비가 몇 분기(0~4) 뒤 매출(최근 4분기)의 전년 대비와 가장 같이 움직였나 — 지난 6년(재무 매트릭스 `QTR_YEARS=6`), 겹친 분기 8개↑,
  상관 0.4 미만은 '뚜렷하지 않음'. 추세가 같은 방향이면 상관이 부풀 수 있어 참고용.
- 판정(규칙): 잔고 · 선수금 − 매출 ≥ +15%p '매출이 따라올 여지' / ≤ −15%p '둔화가 먼저 보이는 자리', 재고+계약자산 − 매출 ≥ +20%p(앞단도 늘었으면 '납품 앞둔 생산',
  아니면 '쌓이는 재고'), 설비 투자 +50%↑, 순이익 − 주가 ≥ +30%p '가격이 덜 따라옴' / ≤ −30%p '가격이 앞서 감'.
- **값(각 분기 말 + 지금)**: 자기 역사 PER 백분위(그날 실제 종가 ÷ 최근 4분기 기본 EPS, 그 분기까지 최근 10년 · 8분기↑ — 손익 매트릭스는 `IS_YEARS=10`),
  하위 30% 싸다 · 상위 30% 비싸다 / 성장 대비 PER(PEG = PER ÷ 지배순이익 성장률, 성장률 1~100%로 묶음) 1 미만 싸다 · 2 초과 비싸다 /
  영업이익률 자기 역사 위치 — 상위 10%면 '이익 꼭대기라 낮은 PER 이 착시일 수 있다'(경기 순환주). 판정 줄 '값'은 오늘 종가 기준으로 두 잣대를 겹쳐 한 문장.
  예: HD현대일렉트릭 지금 PER 29배(10년 상위 39%, 중앙 25배) · PEG 0.5 → '역사 중간대, 성장 대비로는 싸다 + 이익률 역사 최고 경고',
  한화오션 PER 12배(하위 19%) · PEG 0.1 → '싸다 + 이익률 역사 최고 경고'.
- 예(2026-10-01): HD현대일렉트릭 — 재고+계약자산 → 매출 4분기 뒤(상관 0.76), 잔고 +41% · 선수금 +46% > 매출 +23%, 주가 +92% > 순이익 +57%(PER 34→41배).
  한화오션 — 순이익 +139% vs 주가 +26%(PER 29→15배), 선수금 −28%.

**수주 공시 줄**(2026-10-01) — 거래소 수시공시 '단일판매ㆍ공급계약체결'(최근 매출의 5% · 대기업 2.5% 이상 큰 계약). 분기보고서 잔고보다 최대 석 달 먼저.
목록은 DART `list.json`(고유번호 · 거래소공시 `pblntf_ty=I`, 2014년부터, 12시간 캐시 `.cache/수주공시/<코드>.json`), 금액 · 상대 · 기간은 원문 `document.xml`
(`시너지.contract` 파서, 영구 캐시 `.cache/시너지/계약/`). 기재정정은 같은 계약의 수정이라 흐름에서 빼고, 해지는 건수만.
칸 = 최근 4분기 공시 수주 합 ÷ 최근 4분기 매출(%) · 아래 작은 글씨 = 그 합의 전년 대비. '지금' 칸 = 지난 분기 말 뒤 새 공시 합(건수).

## 가속도 — 2차 미분 읽는 법 (가속도 탭, 계산은 화면의 `drkCalc`)

분기 단독 증감률은 수주·납품 시점 때문에 분기마다 ±30%p 널뛴다. 판단은 **TTM(최근 4분기 합)** 으로 한다.

- **성장률** = TTM 매출 / 4분기 전 TTM − 1. **가속** = 그 성장률의 **최근 2분기 평균 변화**(분기당 %p).
  분기당 0.5%p 안쪽은 '속도 유지'로 보고 가속·감속이라 부르지 않는다.
- **국면** = 성장률 부호 × 가속 부호: 바닥 통과(− , +) → 가속 성장(+, +) → 감속 성장(+, −) → 역성장 심화(−, −).
  전형적으로 시계 방향으로 돈다. 드러켄밀러는 바닥 통과에서 들어가고 감속 성장에서 경계한다.
  색은 `validate_palette` 로 짙은 판 위 3색(파랑·초록·주황)을 검증했고, 네 번째 색은 전부 탈락해 역성장 심화는 회색 + 칸 이름.
- **체크리스트** — 가속, 가속 지속(2분기+), 영업 레버리지(이익 증가율 > 매출), 마진 확장(1년), 재고일수(1년 +10% 이상이면서 감속이면 ✕),
  채권일수(1년 +10% 이상이면 ✕), 주가 vs 이익(1년 주가 상승이 EPS 상승보다 30%p 넘게 크면 !).
- **변곡** = 가속의 부호가 바뀐 분기(분기당 1.5%p 이상). **변곡 성적표**는 그 분기 보고서 접수일 종가에서 2·4분기 뒤 주가 —
  그날 알 수 있던 정보만 쓴다. '아무 분기에나 샀을 때' 중앙값과 견준다. 표본이 3번 미만이면 참고만 하라고 적는다.
- **주가 vs 이익** 판은 3년 전(=100) 기준 로그 눈금. 이익이 0 근처인 해를 기준으로 잡으면 지수가 수천으로 부풀어서.
- **분기 궤적 판의 매출 성장률 막대**는 버튼으로 **분기 전년 대비**와 **4분기 합 전년 대비**(TTM)를 오간다(`S.drkRev`).
  - 4분기 합 모드에서는 막대가 추세 자체다. 금색 = 성장, 파랑 = 역성장. TTM 선은 가늘게 겹친다.
  - 세로 눈금은 분기 막대의 극단값 없이 TTM 범위로 다시 잡는다.

## 섹션 궤적 — 다시 쓴 비율 (섹션 궤적 탭, `/api/traj`)

- 한 섹션을 **같은 종류(사업·반기·분기)의 직전 보고서**와 문단 단위로 맞댄다(difflib). 예전엔 바로 앞 보고서와 견줘서
  분기→사업보고서 넘어갈 때마다 서식 차이가 변화로 잡혔다. 정정 공시는 뺀다.
- **숫자는 가리고** 견준다. 금액·날짜만 갱신한 문단까지 세면 평소가 40%대로 부풀어 신호가 묻힌다(가린 뒤 17–28%).
- 다시 쓴 비율 = 100 − 유사도. 등급: 절반 이상(50%+) · 크게 고침(이 섹션 중앙값 +10%p) · 평소 · 거의 그대로(5% 미만).
- 위 판의 분량 선은 한 종류로만 잇는다(고른 종류, 없으면 사업보고서) — 분기보고서는 사업의 내용을 짧게 쓰는 회사가 많다.
- 한 줄 요약은 궤도 탭과 같은 규칙(`_section_line`). 결과는 `.cache/traj/{code}.json`, 비교 규칙을 바꾸면 `TRAJ_V`,
  요약 규칙은 `GIST_V`. 첫 화면 1초 안, 나머지는 뒤에서 채운다(37건 약 5초).

## 호재기업 → 수주잔고 증가 → 억울한 낙폭 (`/api/dip`, 서버 `dip_view`, 2026-09-29)

수주잔고는 쌓이는데 주가는 매크로·심리만으로 빠진 회사를 찾는다. 돈을 벌고 있고, 주주 몫을 해친 일이 없는 곳만 남긴다. 여섯 관문을 차례로 넘어야 한다.
`(참고)`·`(주의)` 표시가 붙은 항목은 탈락 사유가 아니라 참고·주의로만 쓴다. `(등급)` 항목은 탈락시키지 않고 '억울'과 '관찰' 중 어디에 둘지를 가른다.

1. **잔고**
   - 수주잔고를 표 산술로 검산했거나, 회사가 문장으로 밝혀 믿을 수 있다.
   - 꾸준히 증가했거나, 1년 전보다 +15%↑.
   - 북투빌 ≥ 1: 새로 따낸 수주가 그 사이 매출로 빠져나간 것보다 많다.
2. **돈**
   - 최근 4분기 영업이익·순이익이 흑자다.
   - 3년 누적 영업현금흐름이 흑자다.
   - 순차입금 ≤ 자본의 100%.
   - 매출이 1년 전보다 5% 넘게 줄지 않았다.
   - 영업이익률이 5%p 넘게 무너지지 않았다(저가 수주 아님).
   - (주의) 매출채권+재고 일수가 1년에 35%↑ 늘지 않았다. 수주산업의 미청구공사 위험을 거른다.
3. **주주가치** — DART 공시 목록 3년 치를 보고서 이름으로 거른 뒤, 주요사항보고서 세부 API로 다시 판정한다.
   - 쓰는 세부 API: `piicDecsn`·`cvbdIsDecsn`·`bdwtIsDecsn`·`exbdIsDecsn`·`cmpDvDecsn`·`crDecsn`·`tsstkDpDecsn`. 세부 API가 없는 횡령·배임은 공시 본문(`document.xml`)을 읽는다.
   - 탈락:
     - 운영·채무상환 자금 목적의 유상증자.
     - 주주배정이 아닌 방식의 10%↑ 희석.
     - 희석 20%↑ 제3자배정.
     - 사모 CB·BW 중 리픽싱 조항이 있는 것(희석 3%↑), 또는 희석 10%↑인 것. 리픽싱 필드는 `act_mktprcfl_cvprc_lwtrsprc`.
     - 물적분할.
     - 유상감자, 결손 보전 무상감자.
     - 횡령·배임(자기자본 1%↑), 감사의견 비적정·계속기업 불확실성, 관리종목·투자주의환기·불성실공시법인 지정·부도·회생.
   - 주의:
     - 시설자금 주주배정 증자(희석 10%↑여도 증설 목적이면 주의로만).
     - 교환사채, 자기주식 시장 매각(장내·시간외, 또는 목적이 교환사채·재무구조·운영자금), 최대주주 변경, 인적분할, 20% 미만 제3자배정.
     - 리픽싱 없는 10% 미만 사모 사채(예: 파크시스템스 2026 시가 발행 신종자본 BW).
     - 이름에 '예고'·'우려'가 붙은 공시(확정 전). 뒤에 '미지정'·'지정유예' 공시가 나오면 뺀다(예: 한화에어로스페이스 2025.04 예고 → 2025.05 미지정).
   - 뺀다:
     - '종속회사의 주요경영사항'·'자회사의 주요경영사항'. 본사 주주 몫과 따로 본다.
     - 상장일 30일 전후까지의 유상증자(상장 공모, 예: LG씨엔에스 2024.12).
     - 임직원·이사 보상(RSU·RSA·Stock Grant·상여·우리사주·주식매수선택권)용 자기주식 처분(`tsstkDpDecsn`의 `dp_pp`).
     - 다른 회사(자회사) 주식으로 바꿔 주는 교환사채(`exbdIsDecsn`의 `extg`, 예: HD한국조선해양 → HD현대중공업 주식). 이 회사 주식 수와 무관하다.
     - 자기주식 소각 감자(`cr_mth`). 주주 환원으로 따로 ✓ 표시한다(예: 삼성물산·LG).
     - 횡령·배임 공시 중 본문(document.xml)에 무죄·무혐의·불기소가 있는 것(예: 삼성물산 2025.07 대법원 무죄 확정).
     - 이름에 미지정·지정유예·해제·미해당·이전상장·지정취소가 있는 것. 급등 경고(투자경고·투자위험)는 회사 잘못이 아니라서 보지 않는다.
   - 세부 API가 같은 날 여러 건을 돌려주면 접수번호가 같은 것을 쓴다.
4. **하락**: 52주 고점 대비 −20%↓.
5. **억울함**
   - 고점 무렵보다 지금 이익(순이익 4분기 합, 적자면 영업이익)이 5% 넘게 줄지 않았다.
   - (등급) 같은 기간(이 회사 고점일 → 오늘) 시장 −8%↓ 또는 업종 −10%↓.
   - (등급) 시장·업종 중 약한 쪽보다 25%p 넘게 더 빠지지 않았다.
   - (참고) 값 매김(PER)이 15%↑ 줄었다. 과거 검증에서 일관된 관계가 없어 점수에서 뺐다.
   - 시장·업종 수익률 = 수집한 전 종목(업종은 그 회사를 뺀 5곳 이상)의 같은 기간 수익률 **중앙값**. 날마다 중앙값 수익률을 곱해 잇는 지수는 쓰지 않는다 — 아래로 크게 쏠린다(2025.11~2026.9 종목 중앙값 +1%인데 이은 지수는 −47%).
6. **싸다**
   - (등급) 지금 PER이 자기 15년 PER 중 상위 20% 안(`DIP_PRICEY`=80 백분위↑)이면 '관찰'. 크게 빠져도 역사적 고평가면 제자리로 오는 중일 수 있다.
   - (참고) 자기 역사 위치. 풍경 탭과 같은 계산(분할 보정). 과거 검증에서 일관된 관계가 없어 점수에서 뺐다.
   - 풍경을 처음 만드는 회사는 곳당 1분 가까이 걸려, 여섯째 관문은 다섯 관문을 다 돈 뒤 셋씩 나란히 채운다.

**결과 묶음**
- **억울한 낙폭**: 1~5 관문을 넘었고, 세 `(등급)` 조건을 모두 채웠다 — 시장·업종이 함께 빠졌고, 회사만 유독 더 빠지지 않았고, 자기 역사로 봐도 비싸지 않다.
- **관찰**: 1~5 관문은 넘었지만 `(등급)` 조건 중 하나가 걸린다. 걸린 이유를 종목 이름 아래에 적는다.
- **잔고는 느는데 막힌 회사**: 첫 관문(잔고)을 넘고 뒤에서 막힌 곳. 처음 막힌 관문과 이유, 그 밖에 걸린 조건 수를 함께 보인다.

## 호재기업 → 시너지 발굴 (`시너지.py`)

수주가 **실적과 주가로 넘어가는 길목**을 찾는 순위표. 따로 보면 흔한 신호 넷을 한 줄에 세운다.

| 축 | 무엇을 보나 | 어디서 |
|---|---|---|
| **선행** (35) | **북투빌**(50%) = 1 + 잔고 1년 증가분 ÷ 최근 4분기 매출, **잔고/연매출 배수의 1년 변화**(50%) = 지금 잔고÷4분기 매출 − 1년 전 잔고÷그때 4분기 매출 | 정기보고서 수주상황 표 |
| **전환** (25) | **4분기 합** 영업이익률이 낮을수록(늘어날 여지 — 적자는 0%로 묶음) | 분기 단독 실적 4개 합 |
| **확인** (15) | 마지막 정기보고서 **이후** 공시된 단일판매·공급계약 — 금액 합계 ÷ 연매출 | 거래소 공시 원문(계약금액·매출액대비% 정형 칸) |
| **가격** (25) | **반영 갭** = 수주잔고 1년 증가율 − 주가 1년 수익률 | 네이버 일별 시세 |

괄호 안은 가중치. 잔고 값을 믿을 수 있는 회사(검산·명시 값이 절반 이상, 튀는 값 없음)끼리
백분위를 매긴다. 최근 40일 안의 악재 공시(사채 발행·소송·감사 문제 등) 하나당 10점 감점.

단계:

| 단계 | 조건 요지 | 의미 |
|---|---|---|
| **잠복** | 잔고 +15% 이상, 북투빌 1.1 이상, 매출은 아직 덜 따라오고, 주가 상승 < 잔고 증가 | 가장 이른 자리 |
| **점화** | 잔고 +10% 이상, 매출 가속 > 0, 이익률 유지·개선 | 수주가 실적으로 넘어오는 중 |
| **반영** | 주가 1년 +50% 이상이면서 잔고 증가의 1.5배 넘게 올랐거나 PER 40배 이상 | 늦게 따라붙는 자리 |
| **둔화** | 잔고 감소 또는 북투빌 0.9 미만 | 잔고 소진 중 |

산점도는 x=수주잔고 1년 증가율, y=주가 1년 수익률. 대각선 아래(색칠한 곳)가 "수주만큼 주가가 안 오른" 회사다.

**과거 검증** (`도구/시너지_백테스트.py`, 2026-09-30)
- 방법: 2013.06~2025.09 매달 말, 그때 공시된 보고서만으로 이 화면의 행을 다시 만든다. 점수는 `시너지.score()`, 단계는 `stage()`를 그대로 부른다. 그 뒤 12개월 수익률을 같은 기간 전 종목 중앙값과 비교한다(6,823건·122곳).
  - 억울한 낙폭 백테스트의 시점 재구성을 그대로 쓴다.
  - PER은 종목.txt 시가총액 스냅샷에 수정주가 변화를 곱해 근사한다.
- 단계별 12개월 초과수익 중앙값: 잠복 +8%, 점화 +10%, 반영 +10%, 관찰 +5%, **둔화 −1%**.
  - 둔화만 앞뒤 기간 모두 뒤처졌다(−2% / −1%).
  - 잠복·점화·반영은 90% 구간이 겹쳐 구분되지 않는다.
  - '반영'은 2019년 전엔 −5%, 2020년 뒤엔 +17%(모멘텀)였다.
- 예전 점수(선행 = 잔고 증가 .6·북투빌 .4, 전환 = 매출 가속 .6·이익률 변화 .4, 가격 = 반영 갭 .6·PER .4)는 날짜별 IC +0.060, 상위⅓−하위⅓ +8%p.
- 항목별로 보면:
  - 북투빌(+14%p)이 잔고 증가율(+11%p)보다 강했다.
  - 매출 가속은 IC 0.00으로 관계가 없었다.
  - PER·주가 1년도 관계가 없었다.
  - 영업이익률 **수준**은 낮을수록 좋았다(−6%p, 앞뒤 기간 같은 방향).
    - 구간별로는 3~6% +10%, 6~10% +1%, 10~15% −3%였다.
    - 적자(+6%)는 0~3%(+5%)와 비슷했다. 그래서 적자는 0%로 묶어, 적자가 깊을수록 점수가 오르지 않게 했다. 예측력은 같다(IC 0.089).
- 그래서 부분 안의 항목을 바꿨다(부분 가중치 35·25·15·25는 그대로).
  - 지금 점수: IC +0.095, t 2.37(앞 +0.098 / 뒤 +0.092), 상위⅓−하위⅓ +10.7%p(90% 구간 +7.1 ~ +15.2).
  - 전환 부분 IC는 0.004에서 0.079가 됐다.
- 잔고를 몇 년 치로 볼까(2026-09-30):
  - 기간은 1년이 가장 좋았다.
    - 잔고 변화 IC: 3개월 .036, 6개월 .056, **1년 .069**, 2년 연율 .029, 3년 연율 .041.
    - 북투빌 IC: 1분기 .030, 2분기 .072, **1년 .075**, 2년 .023.
    - 짧으면 분기마다 흔들리는 잡음이 크고, 길면 이미 주가에 반영된 이야기다.
  - 잔고 증가율의 가속(석 달 전·1년 전 증가율 대비)과 꾸준함(8개 중 증가 비율)은 약하거나 기간마다 뒤집혔다.
  - 형태로는 '잔고/연매출 배수의 1년 변화'가 가장 고르다.
    - IC .074, t 1.87, 앞 .080 / 뒤 .067. 다른 잔고 지표는 2019년 전엔 약했다.
    - 잔고 증가율은 둔화 판정에 이미 쓰인다. 둔화를 뺀 나머지 안에서는 힘이 없었다.
  - 선행 = 북투빌 .5 + 배수 변화 .5로 바꿨다(배수 변화만 쓴 안과 상위 20% 성과는 오차 안에서 같고, 둘을 섞으면 우연의 위험이 준다).
    - 점수 IC .092 → .095(t 2.37). 앞뒤 기간이 .098 / .092로 고르다.
    - 날짜마다 점수 상위 20%의 12개월 초과수익 중앙값(둔화 뺀 나머지): +12.4% → +14.8%. 2019년 전은 +7.1% → +10.4%.
  - 표의 '수주' 열 묶음에 '배수 1년 변화'를 더했다. 서버 행 필드는 `cover_chg`, `screen_row`는 `매출_TTM_1년전`을 낸다.
- 가온칩스가 1위였던 이유(2026-09-30):
  - 한 분기 이익률(2026Q2 +1.5%)과 직전 분기 대비 변화(−19% → +1.5% = +20.5%p)를 썼기 때문이다. 4분기 합은 영업손실 −91억, 순손실 −55억이었다.
  - 4분기 합 이익률이 한 분기 값보다 강하고 고른 신호였다(−8.4%p, 앞 −7 / 뒤 −10). 전환은 4분기 합 이익률 하나만 쓰도록 바꿨다. 직전 분기 대비 변화는 뺐다.
- 4분기 합 적자 회사(영업이익 또는 순이익 ≤ 0)는 뒤 수익률이 오히려 좋았다.
  - 둔화 뺀 중앙값: 적자 +12.9%, 흑자 +6.5%. 앞뒤 기간 모두 같은 방향이다.
  - 조선·기계·건설·방산을 빼도 +12.2% 대 +6.2%, 회사별 중앙값으로도 +14.6% 대 +3.9%였다.
  - 다만 1년 뒤 −30%↓ 비율이 12% 대 9%로 높다. 망해서 사라진 적자 회사는 표본에 없어(생존 편향) 수준은 부풀어 있다.
  - 그래서 감점도 가산도 하지 않는다. 대신 이렇게 한다:
    - 이름 옆에 '4분기 적자' 표시를 붙이고, 툴팁에 4분기 합 영업이익·순이익을 보인다.
    - 거름에서 '4분기 합 적자인 곳 제외'로 뺄 수 있다.
  - 서버 행에 `op_ttm`·`ni_ttm`·`margin4`·`loss4`를 더했다. `screen_row`는 `순이익_TTM`을 낸다.
- 한계:
  - 점수의 힘은 대부분 둔화를 가르는 데서 나온다. 둔화를 뺀 나머지 안에서는 차이가 작고 불확실하다. 지금 점수는 +4.6%p(90% 구간 −1.6 ~ +10.8)이고, 예전 점수는 −1.2%p였다.
  - 확인(수주 공시)과 악재 감점은 과거 공시 목록이 캐시에 없어 검증하지 못했다.
  - 지금 상장된 회사만 있고, 표본 대부분이 2020년 뒤 사이클이다.

### 스크리너로 쓰기

- **전략 카드** — 카드 하나가 가설 하나다. 잠복 수주주 · 점화 · 역행 수주(잔고 +30%인데 주가 마이너스) ·
  쌓이는 속도 2배(북투빌 ≥ 2) · 3년치 확보 · 저PER 수주 · 마진 레버리지 · 새 계약 러시 ·
  고점 대비 눌림 · 업종 동반 수주 · 과열 점검. 누르면 필터가 그 가설로 바뀐다.
- **직접 설정 필터**(오른쪽) — 시장·대분류·업종·테마·시가총액·단계 / 수주 / 실적 / 계약 / 가격·밸류 / 위험.
  바꾸면 바로 걸러진다. '저장'은 이 브라우저에 필터를 남긴다.
- **열 묶음** — 개요 · 수주 · 실적 · 가격·밸류(1개월·3개월·1년, 52주 고점 대비, RS) · 계약·연결 · 질문.
  머리글을 누르면 정렬, ☆ 는 관심종목(브라우저에 저장).
- **펼친 행** — 근거 / 생각해볼 질문 / 연결. 질문은 숫자 사이의 괴리에서 만든다
  ("연매출 7년치 잔고인데 주가 −74% — 시장은 무엇을 의심하나?"). 연결은 세 갈래:
  계약 공시의 **발주처가 상장사**면 그 회사로(발주를 늘리는 쪽 = 투자를 늘리는 쪽),
  **이 회사에 발주한 곳**, 그리고 **같은 업종 동료**(반영 갭 순).
- **업종 수주 사이클** — 업종마다 잔고 증가 회사 비율, 잔고·주가·반영 갭 중앙값. 어느 업종에 수주가 몰리고
  그중 어디가 덜 반영됐는지. 업종 이름을 누르면 그 업종만 거른다.

시가총액은 `종목.txt` 의 네이버 시총 스냅샷에 그 뒤 주가 변화를 곱한 추정이다.
계약상대 이름은 영문 약자를 한글 읽기로 바꿔 상장사 목록과 맞춘다('LIG…' = '엘아이지…').

## 변곡점 · 구루 렌즈 (`변곡점.py`, 변경점 비교 탭 첫 화면)

15년치 보고서에서 **회사가 꺾인 자리**만 모은다. 숫자(재무 원장)와 문장(「사업의 내용」)을 같이 본다.

- **다섯 갈래** — 정체성(사업 정의가 바뀜, 새 말 등장) · 수익모델(이익률 레벨, 흑자/적자 전환, ROIC 10% 교차,
  이익의 질) · 방향·투자(성장 가속/급감, 분기 가속 전환, 투자 사이클) · 재무·주주(FCF 전환, 차입 급증,
  주주환원 강화, 자사주 매입 시작) · 경고(멍거 역발상 점검에 걸린 것). 칩을 누르면 그 갈래만 남는다.
- **타임라인** — 가로 연도 × 세로 갈래 점. 초록 좋아짐, 빨강 나빠짐, 갈색 경고, 파랑 전환. 점을 누르면 아래 목록의 그 건으로.
- **구루의 렌즈 다섯**
  - 켄 피셔(2026-09-28, 애크먼 대신): PSR = 시가총액 ÷ 최근 4분기 매출(0.75↓ 싸다 · 1.5 적정 · 3↑ 사지 않는다),
    PRR = 시가총액 ÷ 연구개발비(15↓ 싸다; 연구개발비는 사업보고서 「연구개발비 / 매출액 비율」의 당기 값 × 연간 매출 — 비율이 별도 기준인 회사는 근삿값),
    슈퍼 컴퍼니 조건(매출 5년 연평균 15%↑ · 순이익률 5년 평균 5%↑), 일시적 부진(글리치 — 매출은 느는데 순이익률이 직전 3년 평균의 절반 아래).
    시가총액 = 그날 실제 종가 × 그해 말 유통주식수(DART 주식총수). 연도별 PSR 로 'PSR 0.75배 아래로'·'PSR 3배 돌파'·'글리치' 변곡점도 찍는다.
    ROIC·FCF 전환·주주환원 변곡점은 버핏 몫으로 옮겼다.
  - 드러켄밀러: 최근 분기 매출 증가율, 가속(증가율의 변화, %p), 설비투자 강도, 재고일수 — 2차 미분을 본다
  - 버핏: ROE 10년 평균·최저, 영업이익률 흔들림(표준편차/평균), 유보이익 1원 테스트(누적 유보 대비 시가총액 증가)
  - 린치: 저성장·대형우량·고성장·경기순환·회생 분류와 PEG
  - 멍거: 뒤집어 보기 — 이익의 현금화(영업현금 < 순이익 60%), 매출채권 회수 지연, 재고 누적, 과도한 부채(부채/자본 200%+),
    잦은 자본 조달, 적자 지속
- **반영 시계 — "이 보고서는 이미 주가에 반영됐나?"** (2026-09-28, `도구/반영속도_검증.py` → `.cache/반영속도.json` → `/api/pricing_clock`)
  정보 종류마다 값에 드는 속도가 다르다는 문헌을 우리 데이터(14종목, 2015년 이후 정기보고서 515건, 최초 공시일 종가 기준)로 확인했다.

  | 정보 | 문헌 | 우리 데이터 (3·6·12개월 순위상관) | 읽는 법 |
  |---|---|---|---|
  | 매출 증가율(실적 수준) | 잠정실적으로 공시 전 반영 | 종목 안 +0.01 · −0.01 · −0.10 / 종목 사이 +0.04 · 0.00 · +0.03 | **이미 반영** — 드러켄밀러 렌즈는 추세 확인용 |

  | PSR 자기 역사 백분위 | 값(Barbee 외 1996) | +0.06 · **−0.17 · −0.18** (10개 중 8개 음) | **천천히 반영** — 피셔 렌즈는 절대 기준보다 자기 역사 위치로 |

  종목 사이 PSR 은 12개월 +0.13 — 이 시기(2015–2026) 표본에선 비싼 주도주가 더 올랐다. 피셔의 절대 기준(0.75·3배)은 이 표본에서 맞지 않아
  **자기 역사 백분위**를 첫 줄로 올렸다. 렌즈 카드마다 '이미 반영 / 천천히 반영 / 비교용 / 규칙' 표시와 그 렌즈를 쓰는 법, 우리 데이터 12개월 값을 붙였다.
  상관 0.1–0.2는 약하지만 실무 퀀트에서 0.05–0.10이면 쓸 만한 신호로 친다. 표본이 작고 한 시기라 방향만 참고.
- **변곡점 목록** — 해당 보고서와 직전 보고서를 `이 시점 문단 비교 →` 로 바로 열어 원문을 확인한다.
- **정체성의 이동** — 가장 오래된 사업보고서와 최신 사업보고서의 자기 정의 문장을 나란히, 그리고 최근 2개 보고서에만
  있는 말(들어온 말)과 4–6년 전에만 있던 말(나간 말)을 연도별 스파크라인과 함께.

FCF = 영업활동현금흐름 − (유형자산 + 무형자산 취득). 금융업은 이 정의가 맞지 않아 FCF·ROIC 줄이 비거나 약하게 나온다.

## 문단 비교 — 교정지 (변경점 비교 탭 · `/api/diff?v=2`, 서버 `diff_changes`)

예전엔 줄(문단) 단위 diff 라 몇 글자만 바뀌어도 옛 문단 전체(빨강)와 새 문단 전체(초록)가 통째로 나왔고, 표는 칸마다 한 줄이라 숫자 줄이 쏟아졌다.

- 줄 단위로 맞댄 뒤 **옛 문단·새 문단을 짝짓는다**(문자 유사도 50%↑, 순서가 바뀐 문단도 섹션 전체에서 찾는다). 짝이 맞으면 **낱말 단위 diff** —
  바뀐 곳 사이의 짧은 공통부(띄어쓰기·한두 글자)는 흡수해 '뺀 구절 하나 → 넣은 구절 하나'로 읽히게 정리(diff-match-patch 의 semantic cleanup 과 같은 뜻).
- 교정 종류: **새로 씀**(짝 없는 새 문단) · **고쳐 씀**(짝, 그대로 % 표시) · **지움** · **숫자만**(숫자 빼면 같은 문장) · **표**(30자 이하 칸 — 소제목별로 한 장,
  항목·이전·지금·변화%) · **자리 이동**(같은 문단이 4줄 넘게 떨어진 곳으로; 기본 숨김). 제자리에서 띄어쓰기만 고친 곳은 뺀다.
- 화면: 요약 문장 + 종류별 분량 막대(누르면 그 종류를 켜고 끔) · **가장 무거운 변화 셋**(새로 쓰거나 고쳐 쓴 말 가운데 범주·금액·길이로) ·
  교정지 본문(여백에 교정 표시, 소제목 §, 150자 넘게 그대로인 부분은 ⋯ 로 접음, 많이 고친 문단은 '새 문장만') · 오른쪽 미니맵(섹션 전체에서 바뀐 자리, 누르면 이동) ·
  키보드 j/k 로 다음·이전 변화. 기본 비교 짝은 같은 종류의 직전 보고서, '앞 구간/다음 구간'도 같은 종류끼리 한 칸씩.
- 표는 기간이 한 칸씩 밀려(당기→전기) 모든 숫자가 바뀐 것처럼 보이는 경우가 있다 — 표 카드는 접힌 채 앞 8칸만 보인다.

## 말의 궤적 — 키워드로 회사의 궤적을 쫓는다 (키워드 추이 탭, `/api/vocab`, 2026-09-28)

회사가 어떤 말에 지면을 쓰는지는 숫자보다 먼저 움직인다. 이 탭은 쓸 말을 사람이 고르기 전에 먼저 찾아 준다.

- **재는 법**: 보고서마다 「사업의 내용」에서 낱말이 1만 낱말당 몇 번 나오는지 센다.
  - 분기·반기·사업보고서의 길이 차이는 이 비율로 지운다. 선은 4건 평균이다.
  - 어느 회사나 쓰는 말(수요·투자·글로벌)은 전 종목의 흔한 정도(DF)로 누른다.
    - 기준: 전 종목(785개사) 최근 사업보고서의 낱말별 회사 수. `.cache/vocab_df.json`, 30일마다 다시 만든다(약 35초).
    - 80% 넘는 회사가 쓰는 말은 뺀다. 나머지는 흔할수록 순위를 낮춘다.
- **네 갈래**:
  - **떠오른 말**: 최근 4건이 그 전 2년보다 2.5배 넘게 늘었다. 예전에 더 크게 쓰다 돌아온 말은 뺀다. 예: HD현대일렉트릭 BESS·텍사스·계통·풍력, 한미반도체 본더·FC·COB.
  - **주력 말**: 85% 넘는 보고서에 나오고 지면이 안정적이다. 정체성이다.
  - **저문 말**: 4건 평균이 자기 정점의 30% 아래로 내려갔다. 예: 한미반도체 LED·태양광·BMW, 삼성전자 LCD·HHP.
  - **세대 교체**: 같은 약어 뿌리에 숫자 세대가 둘 넘게 붙은 것. 예: DDR3→DDR4→DDR5, LPDDR, HBM2→HBM4.
- **말마다 붙는 정보**:
  - **처음**: 그 말이 한 번이라도 나온 첫 보고서(첫 언급).
  - **본격화**: 그 말의 지면이 가장 크게 한 단계 뛴 보고서.
    - 재는 법: 직전 2건 평균 대비, 그 보고서와 다음 보고서 평균의 오름폭이 가장 큰 곳.
    - 그 오름폭이 보고서 한 건 최고치의 30%에 못 미치면 본격화가 없다(서서히 늘었거나 15년 내내 쓰인 말).
    - 나오자마자 크게 쓴 말(사업부 이름·인수한 회사)은 처음 = 본격화로 한 칸에 적는다.
    - 예전에는 '4건 평균이 정점의 30%에 처음 닿은 보고서'로 정했다. 그러면 평균의 지연 때문에 한 번에 크게 쓴 말도 한 칸 늦게 찍혔고, 티라유텍처럼 뒤늦게 크게 뛴 말은 너무 이르게 찍혔다.
    - 그 보고서 접수일부터 1년 주가도 적는다.
  - **단계 사다리**: 그 말이 든 문장에 개발 / 샘플·인증 / 양산·출시 / 확대 낱말이 처음 나온 보고서.
    - 지금 단계는 최근 2건 기준이다.
    - 문장 셋 중 하나 넘게 둔화·감소를 말하면 '둔화'로 본다.
  - 약어는 낱말 경계로만 센다('SI'가 'LSI' 안에서 세지지 않게).
  - **사건 연표**(`_voc_events`): 그 말이 든 줄에서 날짜가 붙은 사건을 뽑는다.
    - 연혁 목록('- 2024. 5. KOC전기 인수- 2024. 11. 티라유텍 지분 인수- …')은 날짜마다 끊는다. 날짜 뒤에 오는 글이 사건이다.
    - 문장 속에 날짜가 하나뿐이면 그 문장 전체를 사건으로 본다.
    - 기간(2025.06.20 ~ 2026.11.30)은 하나로 묶는다.
    - '현재·기준일' 같은 시점 표기는 사건이 아니므로 뺀다.
    - 금액은 억·조와 MWh로 적는다.
    - 같은 달에 금액이 같거나 글자가 절반 넘게 겹치는 사건은 하나로 합친다. 대신 그 사건이 처음 실린 보고서, 사건 날짜부터 그 보고서 접수까지 걸린 날수, 실린 횟수를 적는다.
    - 그 말이 든 사건을 먼저 10개까지, 같은 문단의 사건은 뒤로 해서 합쳐 14개까지 보인다.
  - **상세 카드**:
    - 뒤늦게 나온 말(9번째 보고서 이후 처음 등장)은 그 말이 나오기 1년 전부터로 확대한다. 이때 가로 눈금은 보고서마다('24.12 사업 / '25.03 분기)다. '15년 전체'로 바꿀 수 있다.
    - 사건은 실제 날짜 자리(달 단위로 보고서 사이를 이음)에 번호 ①②…로 찍는다.
    - 처음·본격화에는 보고서 접수일을 붙인다.
    - 맨 위에 **한 줄씩 읽기**(평문 해석)가 나온다.
      - 언제 처음 나왔나.
      - 지금 이 회사가 「사업의 내용」에서 몇 번째로 많이 쓰는 말인가. 최근 보고서에 몇 번 나왔나.
      - 새 사업인가, **이름만 바뀐 것**인가.
      - 한 번에 자리 잡았나, 사업이 자라며 늘었나.
      - 문장에 나온 단계 낱말.
      - 그때와 1년 뒤 회사 매출(4분기 합) 증가율.
      - 본격화 뒤 1년 주가. 회사 전체 주가라는 단서를 붙인다.
    - 그 아래 **흐름** 칸: 옛 이름 → ① 처음 등장 → ② 본격화 → ③ 지금(또는 마지막). 날짜와 접수일을 붙인다.
    - **이름 바뀜 판정**: 새 말이 처음 나온 보고서의 앞 두 건 ~ 다음 한 건 안에 비슷한 이름의 말이 사라졌으면 개명으로 본다.
      - 비슷함의 기준: 글자 닮음 0.5↑이고 공통 글자 3자↑.
      - 예: 삼성전기 광학통신솔루션 → 광학솔루션(2024년 사업보고서).
      - 사라진 말 쪽에는 '이름 바뀜'으로, 새 말 쪽에는 옛 이름까지 함께 찾는 버튼을 단다.
    - 차트 세로축은 숫자 대신 '많이 씀 / 안 씀'으로 적는다.
      - 튀는 매출 막대(한두 분기)는 90% 분위의 1.6배에서 자르고 값을 적는다.
      - 처음·본격화 꼬리표는 선 아래에, 늘 시간 순서대로(① 왼쪽 → ② 오른쪽) 붙인다. 둘이 붙어 있으면 '① 처음 → ② 본격화' 한 꼬리표로 합친다.
      - 선은 보고서마다의 실제 값이다. 4건 평균은 흐린 점선으로 겹친다.
    - 사건 연표 거르기:
      - 실적 문장(「분기 누계 매출은 …원」)은 사건에서 뺀다.
      - '2025년 3분기'를 3월로 읽지 않는다.
      - 금액 '8조 4,123억원'은 한 덩어리로 읽는다.
    - **주가와의 관계** (`/api/narrative`, 서버 `narrative_view`): 이 말이 그때 실제로 주가를 끌어올린 이야기였나. 뉴스 대신 보고서와 주가로 세 가지를 본다.
      - ① **언제 올랐나**: 이 회사 주가를 세 구간으로 잰다. 첫 언급 전 6개월, 첫 언급 → 본격화, 본격화 뒤 1년. 모두 보고서 접수일 기준이다.
      - ② **시장의 이야기였나**: 전 종목을 훑는다(`_run_theme`, 약 20초, `.cache/theme/`에 저장).
        - '이 말을 쓴 회사' = 그해 사업보고서 「사업의 내용」에 3번 넘게 쓴 회사.
        - '새로 쓰기 시작한 회사' = 그중 2년 전 보고서엔 한 번도 안 쓴 회사.
        - 창(본격화 보고서 1년 전 → 6개월 뒤) 동안 두 무리의 주가 중앙값을 전 종목 중앙값과 견준다. 가격은 캐시(`.cache/price`)를 그대로 읽는다.
        - 새로 쓰기 시작한 회사 이름을 누르면 그 회사로 넘어간다.
      - ③ **무엇이 올렸나**: 같은 창의 주가 = 순이익(4분기 합) 증가 × 값 매김(PER) 변화. 적자면 매출 증가 × PSR 변화로 나눈다.
      - **판정**(`_narr_verdict`):
        - **맞물림**: 이 말을 쓴 회사들의 주가가 시장보다 10%p 넘게 높았고(새로 쓴 곳 8곳↑ 또는 쓴 곳 15곳↑), 이 회사도 상위 30%.
        - **비껴감**: 시장 테마였지만 이 회사는 못 따라감.
        - **겹침**: 회사만의 말. 이 회사 주가가 상위 30%이고 값 매김이 +25%↑ 올랐으며, 말이 커지는 동안 주가도 +30%↑.
          - 말 하나를 떼어 잴 수는 없으므로 '그 이야기였는지는 문장으로 확인'이라고 적는다.
        - **뒤따름**: 첫 언급 전 6개월에 이미 +40%↑ 올랐고, 그 뒤 오름폭은 그 절반도 안 됨. 보고서가 시장을 뒤따라 적은 경우.
        - **부분**: 주가는 올랐지만 이익이 끌었다.
        - **무관**: 주가가 시장보다 못했다.
        - **약함**: 위 어디에도 해당하지 않음.
      - 예(2026-09):
        - 엘에스일렉트릭 '데이터센터' = 맞물림. 쓴 회사 98곳 중앙값 +72%(전체 +24%). 이 회사 +325% = 순이익 +59% × 값 매김 +168%.
        - HD현대일렉트릭 'BESS' = 뒤따름. 첫 언급 전 6개월 +126%.
        - 삼성전기 '광학솔루션' = 약함(개명).
    - 이름 바뀜 판정은 네 가지를 모두 갖춰야 한다.
      - 같은 자리의 앞말(2자↑)이나 뒷말(3자↑)이 남는다.
      - 공통 글자가 3자↑다.
      - 글자 닮음이 0.5↑다.
      - 새 이름이 옛 이름 분량의 0.4~2.5배로 곧바로 시작한다.
      - 빅데이터 → 데이터센터처럼 겹치는 글자의 자리가 바뀐 경우는 개명이 아니다.
    - 매출 막대는 버튼으로 **분기 전년 대비**(그 분기 하나)와 **4분기 합 전년 대비**를 오간다.
      - 분기 하나는 연말 쏠림과 기준 효과에 크게 흔들린다. 예: 엘에스일렉트릭 '24.12 +32% → '25.03 -1%.
      - 4분기 합으로 보면 +8% → +6%로, 추세는 거의 같았다.
- **화면**:
  - 판(EXHIBIT 08): 헤드라인("말이 A에서 B로 옮겨 가고 있다"), 말의 지층(줄마다 면적), 세대 교체 막대, 읽는 법 다섯 가지.
  - 줄을 누르면 아래 카드에 그 말의 지면과 회사 매출 증가율(분기, 전년 대비)을 겹쳐 그린다.
    - 처음 나온 문장 / 본격화 때 / 지금 문장 세 토막을 보인다.
    - 전문검색(문장 족보)과 문단 비교로 넘어갈 수 있다.
  - **직접 견주기**: 쉼표로 넣은 말을 같은 잣대로 겹쳐 그린다(띄어쓰기 무시, 동의어 포함).
- **캐시**: `.cache/vocab/{코드}.json`(`VOC_V`). 첫 계산은 회사당 1–3초.
- **한계**: 단계는 문장 속 낱말로 추정한 것이라 순서가 뒤집혀 보일 수 있다. 보고서가 영문 표기로 쓰는 말은 한글로 찾으면 안 걸린다(파운드리 / Foundry).

## 풍경 — 수십 년치를 처음부터 읽은 사람의 눈 (`/api/landscape`, 서버 `landscape_build`, 2026-09-28)

버핏과 린치가 한 회사의 보고서를 처음부터 끝까지 읽어서 얻는 것은 세 가지다. 이 탭은 그 세 가지를 한 장에 옮긴다.

- **풍경 — 무엇이 보이나**
  - 회사가 어떤 유형으로 살아왔는지 해마다 매긴다. 기준은 린치의 여섯 유형에 적자를 더한 것이다.
    - 고성장: 매출 3년 연 15%↑이고, 최근 4년에 이익이 꺾인 적 없음.
    - 대형우량: 5–15%. 저성장: 5% 미만.
    - 경기순환: 6년 안에 영업이익률 4%↑이던 정점에서 영업이익이 40% 넘게 꺾였거나, 매출이 10% 넘게 줄었음.
    - 회생: 적자 뒤 흑자 첫 두 해. 적자.
  - 같은 유형이 이어진 해들을 한 장(章)으로 묶는다. 장마다 매출 증가율, 이익률, ROE, 주가 수익률, 그 장에 **들어온 말**(「사업의 내용」에서 새로 자주 쓰인 낱말), 변곡점 사건을 붙인다.
  - 그림: 로그 눈금 주가 위에 이익선을 그린다.
    - 이익선 = 최근 4분기 순이익 ÷ 오늘 기준 주식 수 × 자기 역사 PER 중앙값. 띠는 PER 25–75%.
    - 아래 판에는 해마다 ROE를 막대로 그리고, 버핏 기준인 15% 선을 긋는다.
- **안목 — 무엇을 배우나**: 이 회사의 15년에서 뽑은 규칙.
  - 주가가 이익을 따라갔나: 로그 상관.
  - 가장 나빴던 해를 어떻게 버텼나.
  - 번 돈이 어디로 갔나: 영업현금 중 설비·배당·자사주 몫, 주식 수 증감.
  - 유보이익 1원 테스트.
  - 사업 설명의 일관성: 첫해와 마지막 해 「사업의 내용」 낱말 분포의 코사인과, 15년 내내 쓰인 말.
  - ROE의 꾸준함.
- **결단 — 무엇으로 결단하나**
  - 버핏: 네 가지 사업 점검(이해 가능·꾸준함·가벼운 빚·현금이 되는 이익)과 값(자기 역사 PER 하위 25%). 결과는 결단 / 기다림 / 지나침 / 너무 어려움.
  - 린치: 유형별 규칙.
    - 고성장: PEG ≤ 1.
    - 경기순환: 이익이 바닥을 지나 돌아섬. 단, 정점 이익이면 '정점 경계'. 주가가 5년 평균 이익으로 그은 이익선의 2배를 넘으면 '관찰'(과거 B·L 기록도 같은 규칙). 순환주는 이익 바닥에서 PER이 가장 비싸 보이므로 PER로 과열을 재지 않는다.
    - 우량주: 이익선보다 30% 아래.
    - 회생: 흑자 전환 뒤 빚을 버틸 수 있는지.
  - 지금 주가, 이익선, **기다릴 값**(PER 25% 선)을 보인다. 순환주의 기다릴 값은 5년 평균 이익으로 잡는다.
  - **과거 결단 기록 B·L**: 분기 보고서 접수일에 그때까지 알 수 있던 숫자로만 조건을 따진다.
    - 같은 구루는 1년에 한 번만 센다.
    - 1년·3년 뒤 수익률을 '아무 분기에나 샀을 때'와 나란히 보인다.
- **주당 값 보정**
  - 네이버 주가는 수정주가다. 연말 주식 수가 한 해에 1.8배 넘게(또는 0.55배 아래로) 바뀌면 분할·무상증자로 보고, 그 앞 해들의 주식 수를 오늘 기준으로 곱한다. 예: 삼성전자 2018년 ×49.9.
  - 마지막 사업보고서 뒤에 한 분할도 잡는다. 수집된 가장 최근 분기·반기보고서의 주식 수와 비교한다. 예: 엘에스일렉트릭 2026년 5:1. 이것을 안 보면 PER 절댓값이 5배 어긋난다(상대 위치는 그대로).
  - 2015년 이전 주식 수는 DART에 없어 가장 이른 해 값으로 채운다.
  - 그래서 `/api/druck`의 PER_TTM(분할 전 EPS ÷ 수정주가)은 여기서 쓰지 않는다.
- **캐시**: `.cache/landscape/{코드}.json`. 서명에 날짜가 들어가 하루 한 번 주가를 새로 붙인다. 계산은 회사당 1–2초. 규칙을 바꾸면 `LAND_V`를 올린다.
- **한계**: 한 회사 15년의 결단 기록은 표본이 작다. 이 기록은 규칙의 적중률이 아니라 **이 회사가 어떻게 움직이는 회사인지**를 읽는 자료다.

## 전문검색 — 질문 지도와 문장 족보 (`/api/ask`, `/api/lineage`, 2026-09-28)

빈 검색창은 **무엇을 물어야 할지 아는 사람**에게만 쓸모가 있다. 그래서 질문을 먼저 준다.

- **질문 24개, 다섯 주제**:
  - 수요: 수주잔고 · 가동률 · 증설 · 새 매출원 · 정관 사업목적 · 점유율
  - 마진: 판가 · 원가 · 고객 집중 · 환율
  - 자본: 희석 · 자사주 소각 · 배당 정책 · 대주주 주식담보 · 장부 밖 보증
  - 위험: 계속기업 · 핵심감사사항 · 소송·제재 · 대주주 거래 · 내부통제
  - 사람: R&D · 주식 보상 · 최대주주·대표 변경 · 인수·합병
- **질문 하나의 구성** (서버 `ASK_Q`): 정규식 · 찾는 섹션 · 왜 묻나 · 좋은 답 / 나쁜 답 · 구루 · 반영 속도.
  - 반영 속도는 선행 / 천천히 / 꼬리 위험 / 이미 반영 가운데 하나다.
  - 규칙을 바꾸면 `ASK_V` 를 올린다. 캐시는 `.cache/ask/{코드}.json`, 첫 빌드는 4–9초.
- **족보** (`_Lineage`): 같은 문장을 보고서마다 이어 붙인다.
  - 같은 문장으로 보는 기준: 숫자·기간 낱말(당분기/전기…)·띄어쓰기를 지운 뼈대가 같거나, 글자 3-gram 이 절반 넘게 겹치면 같은 말이다(표현을 고친 것).
  - 태어난 때: 처음 나온 보고서.
  - 고쳐 씀: 이전 판에 없던 낱말이 들어온 때. 띄어쓰기만 바꾼 것(스위스연구소→스위스 연구소), 동의어(자사주→자기주식), 두 낱말이 붙은 것은 치지 않는다.
  - 빠짐: 같은 종류 다음 보고서에서 사라진 때. 세 번 넘게 쓰인 문장만 센다. 분기마다 갈아 끼우는 업황 설명은 뺀다.
- **새 답**: 무게(`ASK_SIG` 2.8) 이상인 새 문장이나 고쳐 쓴 문장.
  - 무게가 붙는 요소: 금액, 올해 날짜, 범주 낱말, 꼬리 위험. 문장만 새로 쓴 것은 2.0.
  - 정관 조문체(`~할 수 있다`)·감사 상용구·회계 상용구, 옛 연도만 적힌 연혁 문장은 거른다.
- **평소**: 지난 해들(네 건씩 끊어)의 새 답 개수 중앙값이다.
  - 새 답이 평소보다 많아야 '새 답'이고, 아니면 '평소만큼'이다.
  - 해마다 업황 문장을 갈아 쓰는 삼성전자 같은 회사가 늘 빨갛게 뜨지 않게 하려는 장치다.
- **지금 읽을 줄**: 질문별로 가장 무거운 새 답을 모은 상위 5개. 소송 담합, 특수관계인 자산 매입, 자사주 소각처럼 사람이 먼저 알아야 할 것이 위로 온다.
- **최근 1년 처음 나온 말**: 「사업의 내용」·「경영진단」에서 최근 네 건에 처음 쓰인 명사.
  - 예: 삼성전자 2025-09 '수주총액·수주잔고'(처음 공시), '25-12 'ADAS·S26'.
  - 누르면 그 말의 족보가 열린다.
- **직접 찾기**:
  - 쉼표는 '또는'이다. 한글은 띄어쓰기를 무시한다.
  - 같은 뜻으로 갈라 쓰는 말(`ASK_SYN`: 가동률/가동율, 자사주/자기주식, CB/전환사채…)도 함께 찾는다.
  - 결과는 네 갈래(새로 생긴 말 · 고쳐 쓰였거나 숫자가 움직인 말 · 사라진 말 · 늘 있던 말)와 **표 속 숫자**(표 칸 뒤 네 칸을 붙인 조각의 숫자 궤적 — 예: 평균가동률 95.6→96.1→95.1%)로 나온다.
  - '이 말 곁에 처음 붙은 말'도 보인다.
- **연결**: 문장마다 **본문에서 보기**(그 문장에 형광펜)와 **문단 비교**(처음 나온 때 / 빠진 때를 같은 종류 직전 보고서와 교정지로)가 붙는다.
- **속도**: 본문은 최근 두 회사만 메모리에 둔다(`corpus_text`). 질문 지도를 연 뒤 나머지 섹션을 미리 읽어 두므로 삼성전자도 첫 검색만 약 9초, 이후 1초 안쪽이다.
- **분석 레시피 연결**: 가동률·고객 집중·연구개발비·소송·최대주주 카드는 해당 질문을 바로 연다.
- 옛 평면 목록(`/api/search`)은 서버에 남아 있고 화면에서는 쓰지 않는다.

## 재무지표 (변화 브리핑 상단)

보고서마다 15개 지표를 **직전 같은 종류 보고서 대비 변화량·변화율**과 함께 세운다.

```
PER 28.45배  +17.62배 +162.7%      자산 567조   +52.4조 +10.2%
PBR  2.51배   +1.72배 +217.0%      자본 436조   +34.1조  +8.5%
ROE 10.36%    +1.80%p  +21.0%      부채 131조   +18.3조 +16.3%
EPS 6,605원   +1,655원  +33.4%      유보금 407조 +31.6조  +8.4%
BPS 74,869원  +7,161원  +10.6%      유보율 45,296.2%     +8.4%
                                    부채비율 29.9% +2.0%p +7.2%
```

출처와 계산:

| 지표 | 산출 |
|---|---|
| 자산·부채·자본·자본금·이익잉여금 | DART `fnlttSinglAcntAll` 원장 |
| EPS | DART `기본주당이익` (보고서에 적힌 값 그대로) |
| BPS | 자본총계 ÷ (발행주식총수 − 자기주식), 주식총수는 DART `stockTotqySttus` |
| 부채비율 | 부채총계 ÷ 자본총계 × 100 |
| 유보금 | 자본잉여금 + 이익잉여금 (자본잉여금 없으면 주식발행초과금으로 대체) |
| 유보율 | 유보금 ÷ 자본금 × 100 |
| ROE | 당기순이익 ÷ 자본총계 × 100 (기말 자본 기준) |
| 영업이익률 | 영업이익 ÷ 매출액 × 100 |
| **PER · PBR** | 주가 ÷ EPS, 주가 ÷ BPS. **주가는 네이버 일별 시세**, 그 보고서 **접수일 종가** |

주의:

- **PER 은 사업보고서에서만 낸다.** 분기·반기 EPS 는 누적치라 그대로 나누면 과대평가된다.
  PBR 은 시점 잔액이라 전 기간 산출한다.
- ROE 도 분기·반기는 누적 순이익 기준이라 연율이 아니다.
- 계정을 잡을 때 IFRS 표준태그(`ifrs-full_Assets` 등)를 먼저 보고 없으면 계정명으로 찾는다.
  자본변동표(SCE)는 '자본총계'가 여러 줄 나와 값이 섞이므로 재무상태표·손익계산서만 읽는다.
- 재무 데이터는 `.cache/fin/`, 주가는 `.cache/price/` 에 저장된다. 주가는 하루 단위 갱신.

### DART API 에 원장이 없는 해 — 보고서 본문에서 읽는다 (`본문재무.py`)

`fnlttSinglAcntAll` 은 다음 구간에서 `status 013`(데이터 없음)을 준다.

| 구간 | 대상 |
|---|---|
| 2015~2022 전체 | **금융업**(은행·보험·증권·카드·금융지주 40여 곳: KB금융, 삼성화재, NH투자증권 …) |
| 연간 2014 이전, 분기 2015 이전 | 전 종목 |

이때는 수집해 둔 보고서 본문 「III. 재무에 관한 사항 → 2. 연결재무제표」(2015년 이전은
「XI. 재무제표 등」, 감사보고서 첨부 재무제표)의 표를 읽어 API 원장과 같은 모양으로 쓴다.
그래서 변화 브리핑 매트릭스가 **2011년부터** 나온다.

- 표는 칸이 한 줄씩 풀린 텍스트라, 계정명 뒤 숫자 칸 수를 세어 행을 만든다.
  줄바꿈으로 쪼개진 계정명('X. 영업' '이' '익')은 다시 잇는다.
- 검산이 안 맞는 표는 버린다: 자산 = 부채 + 자본, 기말현금 = 기초 + 증감(+환율).
- 비용을 괄호(음수)로 적은 손익계산서는 비용 줄 부호를 API 원장(양수)에 맞춘다.
- 외화 표시 재무제표(두산밥캣 USD)는 쓰지 않는다. 결산월이 12월이 아닌 회사는
  보고서 종류까지 맞춰 찾는다.
- 검증: API 원장이 있는 해를 본문으로도 읽어 대조했다. 294건 × 7계정(자산·부채·자본·
  매출·영업이익·순이익·EPS)에서 틀린 값 0건(두산밥캣 EPS 2건은 API 쪽이 1,000배 단위 오류).
- 결과는 `.cache/본문재무/` 에 캐시한다. 파서를 고치면 파일 안 `VERSION` 을 올려 새로 읽게 한다.

원장에 **당기순이익 줄이 아예 없는 해**(남해화학 2022, 미래에셋벤처투자 2023 등 귀속분만 적은
경우)는 `법인세비용차감전순이익 − 법인세비용`으로 산출하고 지배+비지배 귀속분과 검산한다.
매트릭스에서 기울임* 으로 표시되고, 마우스를 올리면 산출 근거가 보인다.
같은 방식으로 부채총계가 빠진 해는 `자산총계 − 자본총계`, 중단영업이 없는 해의 순이익은
계속사업이익으로 채운다.

원장 보정 규칙:

- **잘못 붙은 태그**: 롯데렌탈 2021~22 는 매출('영업수익')에 영업이익 태그를 붙여 냈다.
  매출·영업이익·세전이익·순이익처럼 핵심 계정은 이름이 다른 개념을 또렷이 가리키면 이름을 따른다.
- **표 하나만 빠진 원장**: 에프에스티 2015~17 처럼 API 원장에 현금흐름표만 없으면 그 표만 본문에서 보탠다.
- **일시 오류는 캐시하지 않는다**: DART 가 한도 초과(020) 등을 주면 저장하지 않는다.
  저장하면 그 해가 영영 빈 칸으로 남는다. 정상(000)과 데이터 없음(013)만 캐시한다.

`점검_매트릭스.py --all --resume` 은 회사별 결과를 `.cache/점검/부분/` 에 남겨 끊겨도 이어서 돈다.
전 종목은 한 시간 넘게 걸리므로 작업 스케줄러 `GiupChujeok_Audit`(pythonw, 창 없음)로 돌린다.

## 왜 이렇게 만들었나 — 읽는 순서

15년치를 1번 보고서부터 읽는 사람은 없다. 순서는 이렇다.

1. **섹션 궤적**에서 「사업의 내용」 유사도를 본다. 사업보고서끼리 연 단위로.
2. 막대가 짧은 해(= 회사가 문장을 다시 쓴 해)만 3~4개 고른다.
3. 그 구간만 **변경점 비교**로 연다. 초록 문단이 그 해에 새로 생긴 사실이다.
4. 새로 나온 단어를 **키워드 추이**에 넣어 언제부터 몇 번 쓰였는지 본다.
5. **전문검색**으로 그 말의 최초 등장 보고서를 찾아 원문 맥락을 읽는다.

삼성전자 실측: 「사업의 내용」 연 단위 유사도가 2020→2021 구간에 **21.4%**
(63,675자 → 39,793자)로 떨어진다. 15년 중 가장 크게 다시 쓴 해다.
HBM은 2015년 사업보고서에 **1회** 처음 나와 2023년 **31회**까지 늘었다.

## 실행

가장 쉬운 방법 — `기업추적_실행.bat` 더블클릭. `종목.txt` 에 적힌 종목을 최근 10년치 훑는다.
옵션은 bat 에 그대로 붙여도 먹는다: `기업추적_실행.bat --years 15`

```bash
python 기업추적_수집기.py                       # 종목.txt 전체, 최근 10년
python 기업추적_수집기.py 403870 005930         # 종목코드 직접 지정
python 기업추적_수집기.py 005930 --years 15     # 15년치
python 기업추적_수집기.py 005930 --all          # DART 개시(1999)부터 전부
python 기업추적_수집기.py 005930 --from 20100101
python 기업추적_수집기.py 005930 --skip-amended # [기재정정] 건 제외
python 기업추적_수집기.py 005930 --sleep 1.5    # 호출 간격 늘리기
```

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--years N` | 최근 N년 | 10 |
| `--all` | 1999년 DART 개시부터 전부 | — |
| `--from YYYYMMDD` | 시작일 직접 지정 | — |
| `--skip-amended` | `[기재정정]` 재공시 건 제외 | 포함 |
| `--sleep 초` | DART 호출 간격 | 0.8 |
| `--max-calls N` | 이번 실행에서 쓸 DART 호출 상한. `0`이면 무제한 | 18000 |
| `--limit N` | 종목.txt 위에서 N종목만 | 전체 |
| `--with-audit` | 감사보고서도 수집 (상장 전 이력 소급) | 안 함 |

## 상장 전 이력 — `--with-audit`

**정기보고서는 상장사 의무다.** 상장 전에는 아예 존재하지 않는다.
그래서 최근 상장 종목은 `--years 15` 를 줘도 상장 이후만 나온다.

HPSP(2022년 7월 코스닥 상장)가 그 예다. 정기보고서 최초가 2022-09 분기보고서고,
1999년부터 뒤져도 그 앞은 없다.

메우는 길은 **감사보고서**다. 외부감사 대상이면 비상장이어도 매년 제출하고,
재무제표가 통째로 붙어 있다. `--with-audit` 을 주면 같이 받는다.

```
정기보고서 20건 + 감사보고서 4건   접수 20190403 ~ 20260814
   [  1/24] 2018-12 감사보고서   섹션 3개 / 20,771자
```

HPSP는 이걸로 2022 → **2018년**까지 소급됐다. 더는 못 간다 —
2018년 재무제표가 "제 2(당) 기", 즉 2017년 설립이라 회사 이력 자체의 시작점이다.

감사보고서는 섹션이 3개(감사의견 / 재무제표 / 감사 실시내용)뿐이라 정기보고서보다
훨씬 가볍다. 호출 수는 종목당 목록 1회 + 보고서당 1회가 더 든다.

## 수출 추적 — 관세청 통관으로 공시보다 먼저 읽는 매출 (호재기업 옆 탭, `수출추적.py`, `/api/export`, 2026-10-01)

분기 보고서는 분기가 끝나고 45일 뒤에 나오지만, 관세청 통관 수출은 매달 15일께 전월까지 나온다.
회사의 수출 통로를 찾아 두면 아직 공시되지 않은 분기의 매출 방향을 한두 달 먼저 본다.

**1. 거점 — 최근 사업보고서에서** (`profile`)
- 본사: '회사의 개요'의 '본사의 주소'·'본점의 소재지'.
- 공장 후보: '사업의 내용'에서 공장·사업장·조선소·생산 기지 문장 속의 주소 꼴(시도 + 시군구), 또는 관세청 시군구 이름(한 시도에만 있는 이름)과 맞는 도시.
- 주력 제품 → HS 6단위: `HS_DICT`(변압기 8504.21–34, 차단기 8535·8536, 배전반 8537, 선박 8901, 선박엔진 8408, 반도체 장비 8486, 라면 1902.30, 화장품 3304, 톡신 3002.49, 임플란트 9021.29 …). 확신하는 코드만 넣었다.
  가장 많이 언급된 제품의 4분의 1(최소 5번) 넘게 나온 제품만 쓴다 — 부수 품목이 같은 동네 다른 회사의 수출을 끌어오는 것을 막는다(한미반도체의 '기판').
- 관세청 시군구 이름표: `.cache/관세청/_시군구이름.json`(229곳). 구가 있는 시(성남·수원·창원·청주)는 시 단위, 광역시는 구 단위.

**2. 통로 — 실제로 수출이 찍히는 (시군구 × HS)** (`_channels_fast`)
- 관세청 시군구 통계는 **수출자(사업장) 등록 주소** 기준이다. 공장이 별도 사업장이면 공장, 아니면 본사로 잡힌다.
  확인: 삼양식품 라면은 원주·밀양·익산(공장), HD현대일렉트릭 대형 변압기는 경기 성남(본사; 울산 공장 아님).
- 1단계: 2025년 한 해로 후보 (시도 × HS)를 불러 후보 주소에서 30만 달러↑ 찍히는 조합만 남긴다. 2단계: 남은 조합만 2023·2024·2026을 더 부른다.
- 금액 단위는 천 달러(`expUsdAmt`) — 삼양식품 2025년 합 약 11억 달러로 실제와 맞는다.

**3. 검증 — 믿을 만한가** (`validate`)
- 과거 분기(최대 12개) 연결 매출 증가율과 통관 수출 증가율(전년 같은 분기 대비)의 상관.
  신뢰도 A = 상관 0.6↑·8분기↑, B = 0.3↑, C = 그 아래(같은 주소의 다른 회사가 섞였거나 해외 생산·매출 인식 시점이 다른 회사).
- 수출/매출 = 최근 4분기 통관 수출 × 연평균 원/달러(근사) ÷ 연결 매출, 중앙값. 시험: 삼양식품 A(0.76, 57%), HD현대일렉트릭 B(0.51).

**4. 신호** (`signals`, `unit_trend`)
- 최근 3개월 / 직전 3개월 / 12개월 증가율(전년 같은 달 대비), 가속(%p), 마지막 공시 분기 뒤의 달들(공시 뒤).
- 상태: 고성장 유지(두 구간 모두 +20%↑) · 가속(+15%p↑, +10%↑) · 꺾임(−25%p↓, 아직 +5%↑) · 급감 변곡(−25%p↓, +5% 아래) · 감소 전환(−10%↓) · 감소 지속 · 보합.
- 매출 기여 추정 = 최근 3개월 수출 증가율 × 수출/매출 — 내수와 해외 법인 매출은 들어 있지 않다.
- 단가 = 그 품목 전국 수출의 달러/kg, 최근 6개월 vs 전년 같은 6개월(품목국가별 API). 수출이 늘며 단가도 오르면 '단가↑' — 이익에 우호적.
- 주 수출국 = 그 품목 전국 수출의 최근 24개월 국가 비중.

**화면** — 맨 위 '이익에 우호적'(신뢰도 A·B의 고성장 유지·가속, 단가↑ 먼저)과 '변곡 경보'(급감 변곡·꺾임) 두 상자,

**다시 계산**: `python 수출추적.py 전체 [코드,코드]` — 결과 `.cache/수출추적/result.json`(20곳마다 중간 저장), 관세청 응답은 `.cache/관세청/` 캐시를 함께 쓴다.

    금액 단위도 천 달러로 보인다(`expUsdAmt`) — 회사 추정에 쓰기 전에 확인한다.
  - 시군구별은 가장 최근 달이 비어 있을 수 있다(2026-08 울산 850423 빈 결과, 2025년은 나옴).

  - 응답 첫 줄이 합계(`hsCd`·`statCd` = '-')인 경우가 있다.
- 키와 전체 요청 주소는 화면·로그·오류 메시지에 남기지 않는다(오류는 API 이름과 결과코드만).

## 주의

- `.cache/CORPCODE.xml` 은 전체 상장사 고유번호 목록(약 29MB). 하루 지나면 자동 갱신.
  구글 드라이브 동기화가 부담되면 지워도 되고, 다음 실행 때 다시 받는다.
- DART 구버전 문서(대략 2022년 이전)는 줄바꿈을 `&cr;` 라는 자체 엔티티로 쓴다.
  표준 HTML 엔티티가 아니라 파이썬 `html.unescape` 가 모르고 그냥 흘려보낸다.
  `DART_ENTITIES` 에서 개행으로 바꿔준다. 새 엔티티가 나오면 여기 추가하면 된다.
  모르는 `&xxx;` 를 싸잡아 지우지는 않는다 — 본문의 `AT&T;` 같은 걸 다치게 하니까.
  점검: `grep -rhoE "&[a-zA-Z][a-zA-Z0-9]{1,10};" 기업추적_수집 | sort -u` 가 비어야 정상.
- `기업추적_실행.bat` 은 **의도적으로 ASCII만** 쓴다. cmd.exe 가 .bat 안의 한글을
  깨뜨려서 실행이 통째로 실패하기 때문. 한글 출력은 Python 쪽에서 나온다.
  같은 이유로 .bat 은 한글 이름 파이썬 파일을 직접 부르지 않고 `run.py` 를 거친다.
